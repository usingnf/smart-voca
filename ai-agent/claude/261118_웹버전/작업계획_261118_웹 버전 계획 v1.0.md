# 웹 버전 작업 계획 (Web Version Plan)

**파일 위치**: `ai-agent/claude/261118_웹버전/작업계획_261118_웹 버전 계획 v1.0.md`
**작성일**: 2026-11-18
**버전**: v1.0 (결정 사항 확정, 진행 상황 2026-11-18 기준 갱신)
**설명**: 기존 기능을 브라우저에서도 실행할 수 있도록 하는 작업의 단계별 계획. 코어 로직은 재사용하고 화면만 웹으로 새로 만든다.

---

## 1. 현황 분석 결과

| 구분 | 모듈 | PyQt 의존 | 웹에서 재사용 |
|------|------|-----------|---------------|
| 업무 로직 | `session.py`, `quiz.py`, `daily.py`, `report.py` | 없음 | 그대로 사용 |
| 데이터 | `vocab.py`, `user_store.py`, `settings.py` | 없음 | 그대로 사용 (경로만 설정 필요) |
| 온라인 검색 | `online_dict.py` | 없음 | 그대로 사용 |
| 화면 | `ui/*.py`, `main.py`, `crash_log.py` | 있음 | 재사용 안 함. 웹 화면으로 다시 만듦 |

**걸림돌 1 (경로)**: `config.py`의 `BASE_DIR`, `VOCA_PATH`, `USERS_DIR`, `REPORTS_DIR`, `SETTINGS_PATH`는 모듈 로드 시점에 정해진다. 웹 서버가 다른 데이터 폴더를 쓰려면 환경 변수로 덮어쓸 수 있어야 한다.

**걸림돌 2 (화면 흐름)**: 시험 채점, 오답 재시험, 즐겨찾기 등의 흐름 중 일부는 `ui/` 안에 있다. 웹 API를 만들 때 이 흐름을 세션 메서드 호출 순서로 다시 정리해야 한다.

## 2. 결정 사항 (확정 필요)

| 번호 | 결정 | 권장안 | 이유 |
|------|------|--------|------|
| D-1 | 실행 형태 | 로컬 웹 서버 (사용자 PC에서 `python web/run.py` 실행 후 브라우저 접속) | 호스팅 비용이 없고, 사용자 학습 기록이 외부 서버로 나가지 않는다 |
| D-2 | 기술 스택 | 백엔드 FastAPI, 프론트엔드 HTML·CSS·JavaScript (프레임워크 없음) | 파이썬 코드를 그대로 쓰며, 프론트엔드 빌드 도구가 필요 없어 학생이 이해하기 쉽다 |
| D-3 | 데이터 | 웹 전용 데이터 폴더 `data/`를 기본으로 쓰고, exe의 데이터와는 분리 | exe 옆 `users/`와 섞이지 않는다. 환경 변수로 경로 변경 가능 |

> D-1을 공개 호스팅으로 바꾸면 계정 보안, 인증, 서버 비용, 개인정보 처리 방침이 새로 필요하다. 이 계획에는 포함하지 않는다.

## 3. 필요한 승인

| 항목 | 이유 | 상태 |
|------|------|------|
| `fastapi`, `uvicorn` 설치 | 패키지 설치는 CLAUDE.md상 승인 필요 | 미승인 |
| `config.py` 수정 (환경 변수 경로 지원) | 기존 코드 변경 | 미승인 |
| 명세서 개정 (웹 실행 요구사항 추가) | 요구사항 변경은 명세서를 먼저 고친다 (CLAUDE.md) | 미승인 |

## 4. 단계별 계획

### Phase 0. 결정 확정 (현재 단계)
- D-1 ~ D-3 확인
- 위 승인 항목 확인

**완료 기준**: 결정과 승인이 끝남

### Phase 1. 경로 분리
- `config.py`에 환경 변수 `SMARTVOCA_DATA_DIR` 지원 추가 (없으면 기존 동작 유지)
- 기존 exe 동작이 바뀌지 않는지 테스트로 확인

**완료 기준**: 기존 테스트 71개 통과, 환경 변수로 데이터 폴더를 바꿀 수 있음

### Phase 2. 명세서와 API 설계
- 명세서에 FR-13 "웹 브라우저 실행" 추가 (세부 규칙, 추적 매트릭스 포함)
- `web/` 아래 API 목록 정의 (인터페이스 정의서에 추가)

| 엔드포인트 | 메서드 | 대응 세션 메서드 |
|------------|--------|------------------|
| `/api/users` | GET, POST | `list_user_keys`, `UserStore` 생성 |
| `/api/users/{key}` | DELETE | `delete_account` |
| `/api/users/{key}/reset` | POST | `reset_records` |
| `/api/words` | GET, POST | `Vocabulary`, `add_word` |
| `/api/words/{word}` | PUT, DELETE | `update_custom_word`, `delete_custom_word` |
| `/api/search` | GET | `search_by_english`, `search_by_meaning` |
| `/api/online-search` | GET | `search_english_translations` |
| `/api/memorize` | POST | `record_memorize` |
| `/api/assignment` | GET | `today_assignment` |
| `/api/assignment/finish` | POST | `finish_assignment` |
| `/api/quiz` | POST (문항 생성) | `build_questions` |
| `/api/quiz/grade` | POST | `grade_answers`, `record_results` |
| `/api/history` | GET | `history` |
| `/api/report` | GET | `build_summary` |
| `/api/settings` | GET, PUT | `load_settings`, `save_settings` |

**완료 기준**: 명세서와 인터페이스 정의서가 같은 목록을 가짐

### Phase 3. 백엔드 구현
- `web/server.py`: FastAPI 앱, 위 엔드포인트
- 사용자 세션은 요청 간 상태를 서버 메모리에 두지 않는다. 계정 키를 요청마다 받아 `UserSession`을 만든다 (파일이 상태의 원본이다).
- 시험 문항은 서버에서 만들고 정답은 응답에 넣지 않는다. 채점 요청 때 서버가 다시 확인한다.
- 요청 검사: 계정 이름 형식, 문항 수 범위

**완료 기준**: 모든 엔드포인트가 API 테스트를 통과함

### Phase 4. 프론트엔드 구현
- `web/static/index.html`, `app.js`, `style.css`
- 화면 구성 (기존 메뉴 순서 유지)
  1. 계정 선택 (처음 방문 시 계정 만들기)
  2. 암기
  3. 시험
  4. 과제
  5. 단어 추가
  6. 검색 (로컬 + 온라인 보조)
  7. 보고서
  8. 계정 관리
  9. 옵션
- 사용자 친화 요소: 큰 버튼, 진행 막대, 정답·오답 색 표시, 밝게·어둡게 테마, 모바일 화면 대응 (세로 배치)
- 키보드 조작: 암기 화면에서 Enter로 다음 단어 (기존 기능과 맞춤)

**완료 기준**: 주요 흐름(계정 선택 → 암기 → 시험 → 결과 확인)을 브라우저에서 끝까지 진행

### Phase 5. 테스트
- 단위 테스트: 기존 71개 유지
- API 테스트: FastAPI `TestClient`로 엔드포인트별 정상·오류 응답 확인
- 수동 확인: 브라우저에서 주요 흐름, 창 크기 변경 확인

**완료 기준**: 전체 테스트 통과, 수동 확인 체크리스트 완료

### Phase 6. 실행 방법과 문서
- `web/run.py`: 서버 시작 후 기본 브라우저 열기
- 실행 명령: `python web/run.py` (프로젝트 루트에서)
- 문서: 설계서 (웹 아키텍처), 테스트 정의서 추가, 운영 정의서에 웹 실행 절차 추가, 작업 일지
- 문서는 `ai-agent/claude/`에서 작성하고, 승인 후 `docs/`로 승격

**완료 기준**: 새 사용자가 문서만 보고 실행할 수 있음

## 5. 위험과 대응

| 위험 | 대응 |
|------|------|
| 두 화면(exe, 웹)의 동작이 달라짐 | 업무 로직은 한 벌만 쓴다. 화면 흐름 차이는 테스트로 확인 |
| 웹 버전 데이터와 exe 데이터 혼동 | D-3에 따라 데이터 폴더를 분리하고, 실행 시 경로를 화면 하단에 표시 |
| 로컬 서버가 외부에서 접근됨 | 기본 주소를 `127.0.0.1`로만 연다 |
| 동시 쓰기 충돌 | 한 PC에서 한 서버만 실행한다고 가정. 파일 쓰기는 기존 원자적 쓰기 사용 |
| 온라인 검색 키 노출 | 키는 서버 측 `settings.json`에만 두고 화면에는 보내지 않는다 |

### 7.1 계획과 달라진 점

| 항목 | 계획 | 실제 | 이유 |
|------|------|------|------|
| 상태 보관 | 서버는 상태를 두지 않음 | 진행 중 시험 문항만 메모리(최대 50회분)에 둠 | 정답을 브라우저에 보내지 않으려면 서버에 둬야 함. 기록 자체는 파일에 저장 |
| 계정 선택 | 명세서 3.11 | `localStorage` 사용 → 제거 | 3.11은 마지막 계정을 기억하지 않도록 정함 |
| 보안 | 계획에 없음 | `TrustedHostMiddleware` 추가 | DNS 재연결로 로컬 서버를 호출하는 위험 차단 |
| 시험 문항 수 | 5~50 (5 단위) | 서버에서 5의 배수도 검사 | 화면만 막으면 API로 7문항을 만들 수 있었음 (테스트에서 발견) |
| 단어 형식 검사 | 화면 코드 안 | `vocab.WORD_PATTERN`으로 이동 | 웹이 PyQt 모듈을 import하지 않도록 |
