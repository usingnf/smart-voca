## 설계 판단

- **중복 처리**: 이미 있는 단어는 건너뛴다. 기본 단어 4,000개와 겹치면 대부분 건너뛰므로 결과 화면에 건너뛴 개수를 보여 준다. 기존 `add` 화면의 "뜻 합치기"와는 다르다. 가져오기는 새 단어 추가가 목적이기 때문이다.
- **품사**: CSV에 품사가 없으므로 `other`(기타)로 넣는다.
- **일차 기준**: 날짜가 아니라 과제 생성 순서로 센다. 하루를 건너뛰면 날짜와 일차가 달라질 수 있다.
- **이력의 일차**: 암기 기록에만 채운다. 시험 기록은 일차가 없어도 되므로 빈 값으로 둔다.
- **복습 구성 변경**: 설계서 5장의 과제 구성 규칙과 다르다. 설계서를 나중에 고칠 때 함께 반영해야 한다.

- `python -m unittest discover -s tests` — 94개 통과 (기존 78개 + 신규 16개).
  - 기존 테스트 3곳은 새 상태 구조(`assignments`)와 이력 키(`일차`)에 맞게 수정했다. 기대값을 바꾼 것이 아니라 구조를 맞춘 것이다.
- 임시 DB로 API 호출 확인 (`fastapi.testclient`):
  - 가져오기: 형식 오류 2줄 보고, 기본 단어 3개 건너뜀. 새 단어 2개 추가, 파일 안 중복 1개 건너뜀. 조회 시 품사 `other` 확인.
  - 과제 응답: 1일차, 암기 0 / 전체 4000 확인.
  - 가중 출제 시험 생성, 오늘 단어 암기, 이력의 `일차`(1) 기록 확인.
- `node --check`로 `manage.js`, `study.js` 문법 확인.
- 브라우저 화면 동작은 확인하지 않았다. 가져오기 카드와 체크박스는 직접 열어 봐야 한다.
