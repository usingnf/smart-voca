기존 기능을 웹 브라우저에서도 쓸 수 있게 하고, 웹 화면은 사용자 친화적으로 꾸밀 것. 단계별 계획을 세워 진행.

- **계획**: 코드 점검 후 코어 로직(`src/`)에 PyQt 의존이 없음을 확인. 결정 세 가지(로컬 서버, FastAPI + HTML/JS, 데이터 분리)를 사용자에게 확인받음.
- **Phase 1 경로**: `config.py`에 `SMARTVOCA_DATA_DIR` 추가. 기존 동작은 유지. 테스트 3개 추가.
- **Phase 2 명세서**: 명세서 v1.1 → v1.2 (`git mv`로 v1.1을 `docs/old/`로 이동 후 복사). FR-13과 3.20 웹 실행 규칙 추가.
- **Phase 3 백엔드**: `web/app.py` (API 약 30개), `web/quiz_registry.py` (진행 중 시험 메모리 보관), `web/run.py` (127.0.0.1:8765, 기본 브라우저 열기).
- **Phase 4 화면**: `web/static/` (index.html, common.js, study.js, manage.js, app.js, style.css). 메뉴 9개, 밝게·어둡게 테마, 좁은 화면 대응.
- **Phase 5 테스트**: 전체 75개 통과. 웹 API 시나리오 25개는 임시 데이터 폴더에서 실행 (`tests/test_web_api.py`가 래퍼).
- **검증**: `node --check`로 JS 문법 확인. Edge 헤드리스로 화면 로드, 메뉴 9개 생성, 오류 문구 없음 확인.
- **문서 초안**: 설계서, 테스트 정의서, 운영 안내 (`ai-agent/claude/261118_웹버전/`).

## 계획과 달라진 점
- 진행 중 시험 문항은 서버 메모리에 둠 (정답을 브라우저에 보내지 않기 위해). 최대 50회분.
- `localStorage`로 마지막 계정을 기억하던 코드를 제거 (명세서 3.11 준수).
- `TrustedHostMiddleware` 추가: DNS 재연결로 로컬 서버를 호출하는 위험 차단.
- 문항 수 검사에 5의 배수 조건 추가 (테스트에서 7문항 생성이 가능한 것을 발견).
- 단어 형식 검사(`WORD_PATTERN`)를 `ui/study_pages.py`에서 `vocab.py`로 이동 (웹이 PyQt 모듈을 import하지 않도록).

## 발견한 문제와 처리
- 테스트가 같은 계정을 공유해 서로 간섭: 테스트마다 계정을 따로 만들도록 수정.
- 기본 단어장에 있는 단어(`quartz`, `river`)를 "새 단어"로 썼던 테스트 데이터 오류: 가짜 단어로 교체.
- 작업 중 실행한 명령이 권한 거부됨: 테스트 서버를 끄려고 `taskkill /IM python.exe`(모든 Python 프로세스 종료)를 실행하려 했음. 실행되지 않았음. 이후 시간 제한(`timeout`)으로 서버가 저절로 끝나도록 바꿔 확인.
