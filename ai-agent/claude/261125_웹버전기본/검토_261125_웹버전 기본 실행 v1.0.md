---

## 1. 배경

- 데스크톱 버전: PyQt6 창 앱. `src/main.py`로 실행하고 PyInstaller로 `SmartVoca.exe`를 만든다.
- 웹 버전: FastAPI + 정적 HTML/JS. `web/run.py` 또는 `웹실행.bat`으로 실행하고, 학교 서버에는 Docker 이미지로 배포한다.
- 두 버전이 같은 업무 로직(`src/`)과 같은 저장소(`voca.db`)를 쓴다 (2026-11-25 SQLite 전환).

## 2. 대안

| 대안 | 내용 |
|---|---|
| A. 데스크톱 기본 유지 | 기존 exe 중심 운영. 학교 서버 배포와 따로 간다. |
| B. 웹 기본 (채택) | 웹을 기준 버전으로 두고, 기능 추가·문서·배포는 웹 기준으로 한다. |
| C. 두 버전 동등 | 기능과 문서를 양쪽에 맞춘다. 작업량이 두 배가 된다. |

## 3. 결정

**웹 버전을 기본 실행 버전으로 한다.** (결정자: 사용자, 2026-11-25)

## 4. 결정 근거

- 학교 서버 배포 대상이 웹 버전이다 (조건 1~9, Docker 이미지).
- 저장소를 SQLite 한 곳으로 모았기 때문에 웹과 데스크톱을 같이 유지하는 비용이 크다.

## 5. 결정으로 생기는 후속 확인 사항 (미결)

1. **제출물 형식**: `CLAUDE.md`는 "최종 `.exe` 파일 1개만 제출"로 적혀 있다. 웹이 기본이면 제출물을 무엇으로 할지 정해야 한다 (exe 유지 / 웹 실행 파일 / 서버 주소 등).
2. **데스크톱 버전 처리**: 기능 추가를 멈출지, 버그만 고칠지 정해야 한다.
3. **문서 반영**: `docs/`의 설계서·운영 안내·요구사항 명세서에 이 결정을 반영하는 일은 승인 후 진행한다 (`CLAUDE.md` 문서 관리 규칙).
4. **실행 안내**: `웹실행.bat`과 `web/run.py`를 기본 실행 경로로 안내할지 정해야 한다.
