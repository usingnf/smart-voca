## 요청

UI가 웹에서 반응형으로 동작하도록 수정.

## 현황 (수정 전)

- `style.css`에 `@media (max-width: 720px)` 하나만 있었음.
- 넓은 보고서 표는 감싸는 칸이 없어 화면 밖으로 밀려남.
- `.row`에 줄바꿈이 없어 계정 행의 버튼 3개가 화면 밖으로 나감.
- 입력 칸 `min-width: 180px`, 범위 슬라이더 `width: 200px` 고정 → 좁은 화면에서 넘침.
- `.layout`의 `1fr`이 내용 최소 폭에 밀려 사이드 메뉴 옆 본문이 넓어질 수 있음.
- 14일 막대 차트 날짜 라벨이 좁은 화면에서 겹침.

## 처리

| 파일 | 변경 |
|------|------|
| `web/static/style.css` | `.layout`·`.view`에 `minmax(0, 1fr)`·`min-width: 0` 적용, `.row`에 `flex-wrap`, 전체에 `overflow-wrap: break-word`, `.bars` 가로 스크롤과 최소 막대 폭(28px), `.table-scroll` 추가 |
| `web/static/style.css` | 미디어 쿼리 3단계: 960px 이하(태블릿, 메뉴 180px), 720px 이하(메뉴 가로 줄, 입력 칸 전체 폭, 토스트 하단 전체 폭), 480px 이하(글자·카드·통계 칸 축소, 통계 2열) |
| `web/static/manage.js` | 보고서 오답 표를 `.table-scroll`로 한 겹 감싸 칸 안에서만 가로 스크롤 |

## 설계 판단

- 글꼴 크기는 사용자가 옵션에서 정하므로 좁은 화면에서도 강제로 바꾸지 않았다.
- 사이드 메뉴는 720px 이하에서 위쪽 가로 줄로 바꾸는 기존 방식을 유지했다 (메뉴 항목 10개).
- 넓은 표는 줄바꿈 대신 칸 안 가로 스크롤을 택했다 (오답 단어의 열 내용을 줄이지 않기 위함).

## 검증

- `python -m unittest discover -s tests` — 75개 통과.
- `node --check web/static/manage.js` — 문법 이상 없음.
- Edge 헤드리스 캡처 (Windows 창 최소 폭 때문에 `--window-size`로는 좁은 폭을 재현할 수 없어 폭을 지정한 iframe에 넣어 확인):
  - 360px·390px(휴대폰): 계정 관리 행 버튼 줄바꿈, 통계 2열, 막대 차트 가로 스크롤 확인.
  - 800px(태블릿 구간): 사이드 메뉴와 본문 정상.
- 암기·시험·보고서 화면은 로그인 후에만 열려서, 보고서는 같은 CSS를 쓰는 임시 목업으로 확인했다. 실제 로그인 후 화면은 사용자가 직접 확인 필요.
