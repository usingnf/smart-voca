## 1. 기술 결정 (ADR)

| 항목 | 결정 | 배경·근거 |
|------|------|-----------|
| 언어 | Python 3.11.4 | PC 설치본 중 최신 |
| GUI | PyQt6 6.11.0 | 사용자 지정 |
| 배포 | PyInstaller 단일 exe (`--onefile --windowed`) | 사용자 지정, 제출물은 exe 1개 |
| 단어 저장 | `voca.csv` (기본 데이터), 사용자별 `words.csv` (추가 단어) | 요구사항의 CSV 기반 DB, 추가 단어도 같은 형식 |
| 상태 저장 | 사용자별 `state.json` (과제, 대기열, 오답 통계, 암기 기록) | 중첩 구조는 CSV보다 JSON이 적합 |
| 이력 저장 | 사용자별 `history.csv` | 확정 규칙: 이력은 CSV, 사용자별 파일 하나 |
| 유사 의미 | `voca.csv`의 `유의어` 열 | 확정 규칙: 검색 대상 2000개 + 사용자 추가 단어 |
| 테마 | Fusion 스타일 + 팔레트 전환 | 시안에서 확인한 방식 |
| 저장 방식 | 임시 파일 작성 후 교체 | 확정 규칙: 백업 없이 손상 위험 감소 |

SQLite는 쓰지 않는다. 데이터 규모(단어 2000개, 사용자 소수)에 비해 과하고, 요구사항이 CSV 이력을 명시했다.

`voca.csv`가 없으면 안내 창을 띄우고 종료한다.

## 4. 단어 풀과 정규화

- 기본 풀: `voca.csv`에서 **한글 뜻이 빈 행을 제외**하고 로드한다.
- 사용자 풀: 기본 풀에 `words.csv`를 덮어쓴 결과다. 같은 단어가 있으면 사용자 항목이 우선한다.
- 단어 추가 시 같은 단어가 있으면 경고를 띄우고 뜻을 **합친다** (순서 유지, 중복 제거). 기본 단어는 품사·유의어를 그대로 가져온다.
- 정답 비교: 공백 제거 + 소문자 변환. 복수 정답은 `accepted` 목록의 하나와 일치하면 정답.

## 5. 일일 과제 알고리즘 (FR-04)

기준 날짜는 KST 날짜다. 계정을 처음 만든 날부터 과제를 시작한다.

1. 오늘 날짜의 과제가 있으면 그대로 반환한다.
2. 없으면 기존 `pending` 과제를 모두 `missed`로 바꾸고, 그 과제의 단어 20개를 `queue`(복습 대기열) 뒤에 넣는다.
3. 복습 비율 `r = uniform(0.10, 0.50)`, 복습 수 `R = round(20 × r)` (2~10개).
4. 복습 단어 선정 (최대 R개):
   - 대기열(`queue`)에서 앞에서부터 꺼낸다. 남은 단어는 대기열에 남아 다음 날로 이월된다.
   - 부족하면 **전날 암기한 단어**(`memorized[어제]`)에서 무작위로 채운다.
5. 신규 수 `N = 20 − 복습 수`. 신규 단어는 풀에서 **이전 과제에 나온 적 없는** 단어를 무작위로 뽑는다.
6. 신규 단어가 부족하면(전체 소진) **오답률이 높은 단어**를 복습 단어로 추가한다. 오답률 = 오답 수 ÷ 출제 수.
7. 과제 기록: `{date, words, review, new, status: pending, score: null}`.

완수 판정: 과제 시험 정답률 ≥ 80%이면 `completed`로 바꾼다. 중도 종료는 미이수로 둔다.

## 6. 문항 구성과 채점 (FR-03, FR-06, FR-07)

- **문제 수**: 일반 시험은 5~50 (5 단위, 기본 20). 과제 시험은 과제 단어 20개 전체.
- **출제 품사 (구현 중 추가, 2026-10-21 사용자 요청)**: 일반 시험에서 명사·동사·형용사·부사·기타 중 하나 이상을 고르면, 정답 단어는 그 품사에 속한 단어에서만 뽑는다. 한 단어가 여러 품사(`noun, verb`)이면 하나라도 맞으면 포함한다. 보기(오답 후보)는 전체 풀에서 고르고, 같은 품사 우선 규칙을 따른다. 선택 가능 단어가 문제 수보다 적으면 그 수로 줄이고 안내한다. 과제 시험에는 적용하지 않는다.
- **유형 배분**: 선택한 유형을 균등 배분하고, 나머지는 앞 유형부터 1개씩 더한다.
- **방향**: 영어→한글, 한글→영어, 복합(문항마다 50:50, 섞은 뒤 배정).
  - 과제 시험의 방향은 **복합**으로 한다. 요구사항에 명시가 없어 설계 판단으로 정했다.
- **4지선다**: 정답 1 + 오답 3, 보기 순서 무작위.
- **OX**: 정답 O 50%, X 50%. X는 다른 단어의 뜻(또는 단어)을 붙여 만든다. 참/거짓 배정은 미리 정한 목록을 섞어서 정확히 절반이 되게 한다.
- **오답 보기 선택**:
  1. 같은 품사의 단어만 후보로 한다 (없으면 전체).
  2. 정답 단어와 뜻이 겹치는 단어는 제외한다.
  3. 철자 유사도(`difflib.SequenceMatcher`)가 높은 상위 10개 중에서 무작위로 고른다.
- **채점**: 답 문자열을 정규화한 뒤 `accepted` 목록과 비교한다. 결과 화면에서 틀린 문항은 정답을 함께 보여 준다.

## 7. 기록

- `history.csv` 열: 일시(KST, ISO), 구분(암기/시험/과제시험), 단어, 방향, 유형, 결과(정답/오답/열람), 입력값, 정답
- 암기 열람: `memorized[오늘]`에 단어를 추가하고 구분 "암기" 행을 남긴다. 오답률에는 넣지 않는다.
- 시험 결과: `stats[단어]`의 출제·오답 수를 올린다.

## 8. 보고서 (FR-09)

- 기간: 전체 / 최근 7일 / 최근 30일 / 시작·끝 날짜 지정
- 항목
  - 과제 이수율 = 완수 과제 ÷ (완수 + 미이수) 과제, 기간 내 기준
  - 암기한 단어 수 = 기간 내 암기 열람 단어의 고유 개수
  - 오답률 상위 10개 = 기간 내 시험 기록 기준, 출제 1회 이상인 단어만, 오답률 내림차순 (같으면 출제 많은 순)
- 출력: `reports/<사용자>_<날짜>.html`을 만들고 기본 브라우저로 연다.

## 9. 계정

- 사용자명: 영문·숫자·한글 1~20자. 폴더 이름은 소문자로 저장하므로 대소문자를 구분하지 않는다.
- 로그인: 사용자명만 입력하며 비밀번호는 없다. 프로그램 실행 시마다 입력한다.
- 계정 전환: 메인 창 왼쪽 하단 버튼으로 로그인 창을 다시 띄운다. (구현 중 추가한 항목이며, 여러 명이 한 PC를 나눠 쓰는 요구를 충족하기 위함)
- 초기화: `state.json`, `history.csv`를 비운다. `words.csv`는 남긴다.
- 삭제: 계정 폴더 전체를 지운다.
- 두 작업 모두 실행 전에 되돌릴 수 없음을 알리는 확인 창을 띄운다.

## 10. 옵션 (구현 중 추가, 2026-10-21 사용자 요청)

- 저장 위치: `BASE_DIR/settings.json` (계정과 무관한 앱 전체 설정)
- 항목과 범위

| 항목 | 값 | 기본값 |
|------|----|--------|
| 테마 | 밝게 / 어둡게 | 밝게 |
| 글꼴 크기 | 9~16pt | 10pt |
| 시험 기본 문제 수 | 5~50 (5 단위) | 20 |
| 시험 기본 방향 | 영어→한글 / 한글→영어 / 복합 | 영어→한글 |
| 암기 기본 방향 | 영어→한글 / 한글→영어 | 영어→한글 |

- 글꼴 크기 대응: 제목·강조 글자는 px가 아닌 **글꼴 단계**(`fontLevel`)로 지정하고, 기본 글꼴 크기의 배수로 계산한다. 창과 메뉴는 고정 크기 대신 최소 크기만 둔다.
- 값을 바꾸면 즉시 저장·적용한다. 잘못된 값은 범위 안의 값으로 고친다.
- 테마 버튼(왼쪽 하단)과 옵션 화면의 테마 항목은 같은 값을 바꾼다.

## 12. 알려진 한계 (구현 기준)

- 사용자 추가 단어는 과제와 시험 풀에 포함된다. 요구사항에 명시되지 않아 설계 판단으로 정했다.
- 여러 날 동안 접속하지 않으면, 중간 날짜는 과제가 없으므로 미이수 기록을 만들지 않는다. 마지막으로 남은 `pending` 과제만 미이수 처리한다.
- 유의어는 뜻별로 구분하지 않는다 (데이터 한계).
