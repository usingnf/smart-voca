# 웹 테스트 정의서 (Web Test Specification)

**파일 위치**: `docs/테스트_261118_웹 테스트 정의서 v1.3.md`
**작성일**: 2026-11-18
**버전**: v1.3
**설명**: FR-13(웹 실행)의 자동 테스트와 수동 확인 항목을 정의한다. 방법론 §2.4 테스트 정의서의 웹 부분.

---

## 1. 실행 방법

```
python -m unittest discover -s tests -v      (프로젝트 루트)
```

- 전체 107개 (2026-11-26). 래퍼 1개가 웹 API 시나리오 34개를 별도 프로세스에서 실행하므로 unittest 집계에는 시나리오가 따로 나오지 않는다.
- 웹 API 시나리오는 `tests/web_api_cases.py`에 있다. 래퍼 `tests/test_web_api.py`가 임시 폴더를 `SMARTVOCA_DATA_DIR`로 지정하고 별도 프로세스에서 실행한다. 실제 학습 기록(`data/users/`)은 건드리지 않는다.

### 2.3 자동 테스트에서 확인하지 못하는 것

- 브라우저 화면의 클릭, 입력, 키보드 동작
- 화면 배치와 테마 색
- 음성 읽기

## 3. 화면 검증 (실제 실행으로 확인함, 2026-11-18)

| 항목 | 방법 | 결과 |
|------|------|------|
| 화면 로드와 메뉴 생성 | Edge 헤드리스로 `/` 렌더링 후 DOM 확인 | 메뉴 9개(암기, 시험, 과제, 검색, 단어 추가, 보고서, 옵션, 계정 관리 등) 생성, 오류 문구 없음 |
| 계정 없을 때 이동 | 같은 방법 | 계정 관리 화면으로 이동 |
| 정적 파일 | `/static/*.js`, `style.css` 요청 | 200, 없는 파일은 404 |
| JavaScript 문법 | `node --check` | 네 파일 모두 통과 |

## 5. 알려진 한계

- 자동 테스트는 API 규칙을 확인한다. 화면 동작은 M 항목으로 사람이 확인해야 한다.
- 로그인 화면과 다른 계정 보기는 브라우저 동작을 자동으로 확인하지 않는다. 2026-11-26에 Edge 헤드리스로 로그인 화면이 그려지는 것만 확인했다.
- 가중 출제와 자주 틀린 단어 섞기는 자동 테스트가 분포의 방향만 확인한다. 실제 출제 감각은 4장의 수동 확인(M-15)으로 본다.
- 정답 판정 "통과" 경로(정답률 80% 이상)는 API 테스트에서 직접 만들 수 없다 (정답이 응답에 없음). 통과 기준 자체는 `tests/test_core.py`의 `test_pass_threshold_is_eighty_percent`가 확인한다.
