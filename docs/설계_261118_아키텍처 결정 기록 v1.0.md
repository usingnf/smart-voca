## ADR-01 저장 방식: DB 없이 CSV·JSON 파일 사용

- **배경**: 단어 4000개, 사용자 몇 명 규모. 설치 없이 단일 exe로 배포해야 함.
- **대안**
  1. SQLite 같은 내장 DB (재구성된 대안)
  2. CSV·JSON 파일 (채택)
- **결정 근거**
  - 제출물이 exe 하나이므로 DB 설치나 서버가 필요 없어야 한다.
  - 데이터가 CSV로 바로 열려 학생이 내용을 확인하고 수정하기 쉽다.
  - 쓰기 실패에 대비한 임시 파일 교체로 손상 위험을 줄였다.
- **결과·제약**: 대량 데이터나 동시 접속에는 맞지 않는다. 열 이름 변경 시 호환성 문제가 생긴다.
- **관련**: `데이터 설계서`, `user_store.write_json_atomic`

## ADR-02 GUI 프레임워크: PyQt6

- **배경**: Windows 데스크톱 앱, 한글 표시, 표·탭·대화상자 필요. 단일 exe 배포 가능해야 함.
- **대안**
  1. PyQt6 (채택)
  2. Tkinter (재구성된 대안)
  3. 웹 기반 UI (재구성된 대안)
- **결정 근거**
  - 표, 대화상자, 테마, 스레드를 한 라이브러리에서 제공한다 (`QThread`로 온라인 조회 처리).
  - 설계 시안(`설계_261021_UI 시안`)의 창 구성을 그대로 구현하기 편하다.
- **결과·제약**: PyInstaller로 exe를 만들면 크기가 약 37MB다 (`dist/SmartVoca.exe`, 2026-11-11 기준). 버전은 `requirements.txt`에서 고정한다.

## ADR-03 배포: PyInstaller 단일 파일 + 콘솔 없는 실행

- **배경**: 제출물이 `SmartVoca.exe` 하나여야 함 (CLAUDE.md).
- **대안**
  1. `--onefile --windowed` (채택)
  2. `--onedir` 폴더 배포 (재구성된 대안)
- **결정 근거**
  - 제출 형식이 단일 파일이다.
  - 콘솔 창이 없으면 오류가 사용자에게 보이지 않는다. 이 문제를 ADR-06으로 해결했다.
- **결과·제약**
  - 아이콘 같은 읽기 전용 자원은 임시 폴더(`_MEIPASS`)에서 읽는다 (`config.resource_path`).
  - 사용자 데이터는 exe 옆 폴더를 쓴다. 두 경로를 혼동하지 않는다.

## ADR-04 사용자 데이터 위치: exe 옆 폴더

- **배경**: 단일 exe 배포에서 데이터를 어디에 둘지 정해야 함.
- **대안**
  1. exe 옆 폴더 (채택)
  2. 사용자 AppData 폴더 (재구성된 대안)
- **결정 근거**
  - `voca.csv`가 exe 옆에 있어야 학생이 직접 확인하고 교체할 수 있다 (CLAUDE.md 배포 방식).
  - 데이터를 찾기 쉽고 이동이 간단하다.
- **예외**: 오류 로그만 `%LOCALAPPDATA%\SmartVoca\error.log`에 둔다 (ADR-06). exe 옆 파일을 늘리지 않으려는 목적이다.
- **결과·제약**: exe를 다른 폴더로 옮기면 데이터 경로도 바뀐다.

## ADR-05 단어 데이터 출처: Kaikki (Wiktionary) + 행별 출처 기록

- **배경**: 영단어 4000개와 한국어 뜻·유의어·예문이 필요함. 직접 입력은 비현실적.
- **대안**
  1. Kaikki(Wiktextract) 원시 데이터 추출 (채택)
  2. 직접 작성 (재구성된 대안)
  3. 상용 사전 API (재구성된 대안)
- **결정 근거**
  - 무료이고 로컬에서 처리할 수 있다. 원시 데이터(약 24GB)는 스트리밍으로 읽었다.
  - 라이선스가 CC BY-SA 4.0 / GFDL이라 출처 표시가 가능하다.
  - 행마다 `출처`, `라이선스` 열을 두어 재배포 조건을 데이터와 함께 보존한다.
- **결과·제약**: 유의어 63%, 예문 74%만 채워짐. 뜻별 구분 없음 (`data/README.md`).
- **관련**: `data/README.md`, 커밋 `46389d9`, `9a7d8b5`

## ADR-06 처리되지 않은 오류: 로그 파일 + 안내 창

- **배경**: exe는 콘솔이 없어서 예외가 나면 앱이 조용히 닫혀 원인을 알 수 없었다 (커밋 `874451b` 메시지).
- **대안**
  1. `sys.excepthook`으로 로그 파일 기록과 안내 창 표시 (채택)
  2. 콘솔 창을 보이게 빌드 (재구성된 대안)
  3. 각 화면에서 try/except로 개별 처리 (재구성된 대안)
- **결정 근거**
  - 한 곳에서 모든 미처리 예외를 잡는다.
  - 콘솔을 보이게 하면 배포 형태가 바뀌고 제출 조건에 맞지 않는다.
  - Ctrl+C는 기본 처리를 유지하여 중단 동작을 바꾸지 않는다.
- **결과·제약**: PyQt 슬롯에서 발생한 예외는 Qt가 추가로 종료시킬 수 있다. **확인 필요**: 실제 exe에서 안내 창 뒤에 앱이 닫히는지 실행으로 확인해야 한다 (`일지_261118_처리되지않은오류기록.md`).
- **관련**: `src/crash_log.py`, `tests/test_crash_log.py`

## ADR-07 온라인 검색: 보조 기능, 실패 시 로컬 유지

- **배경**: 한글 검색어에 대한 영어 번역을 더 얻고 싶으나, 학습 기능은 인터넷 없이도 동작해야 함 (FR-12).
- **대안**
  1. 국립국어원 한국어기초사전 API를 보조로 호출 (채택)
  2. 외부 API 없이 로컬 사전만 사용 (재구성된 대안)
- **결정 근거**
  - 무료이며 공식 API다. 출처 표시 조건이 명확하다.
  - 로컬 결과를 먼저 보여 주고 온라인 결과는 별도 영역에 둔다 (명세서 3.14).
  - 시간 초과 5초, 백그라운드 스레드로 화면 멈춤을 막는다.
- **결과·제약**: 인증키를 사용자가 직접 발급받아 입력해야 한다. 키는 `settings.json`에만 둔다.
- **관련**: 일지 `일지_261028_온라인한영검색.md`, 명세서 3.14

## ADR-08 기록 구분 상수 통일 (`TEST_RECORD_KINDS`)

- **배경**: `session.py`와 `report.py`가 "시험", "과제시험" 문자열을 각각 따로 정의하고 있었음 (커밋 `874451b`).
- **대안**
  1. `config.py`에 한 번만 정의하고 모두 가져다 씀 (채택)
  2. 각 모듈에 중복 정의 유지 (현행 이전 상태)
- **결정 근거**: 한 곳을 고치면 보고서와 세션 집계가 함께 맞춰진다. 문자열 직접 사용을 없애 오타를 막는다.
- **결과·제약**: 기록 구분을 추가할 때 `config.py`와 `TEST_RECORD_KINDS`를 함께 고쳐야 한다.

## ADR-09 문서 관리: 명세서를 먼저, 코드를 나중에

- **배경**: 요구사항이 CLAUDE.md에 섞여 있어 변경 이력 추적이 어려웠음.
- **대안**
  1. 명세서를 `docs/`로 분리하고 CLAUDE.md에는 링크만 둠 (채택, 2026-11-11)
  2. CLAUDE.md에 계속 기록 (재구성된 대안)
- **결정 근거**: 방법론 §3-1 추적성, §3-4 문서 기반 소통. 요구사항 ID(FR-xx)를 구현 파일과 연결할 수 있다.
- **결과·제약**: 요구사항 변경 시 명세서 개정(v1.x)과 변경 이력 기록을 먼저 해야 한다.

## ADR-10 문서 위치: `ai-agent/claude/`에서 작성, 승인 후 `docs/`로 승격

- **배경**: AI 작업 산출물과 승인된 산출물을 구분해야 함.
- **대안**
  1. 작업 문서는 `ai-agent/claude/`, 승인 후 `docs/`로 이동 (채택)
  2. 처음부터 `docs/`에 작성 (재구성된 대안)
- **결정 근거**: CLAUDE.md는 Claude가 `docs/`에 직접 쓰지 않도록 정한다. 사람이 승인한 문서만 `docs/`에 둔다.
- **결과·제약**: 현재 `docs/`에는 명세서만 있다. 나머지 산출물은 승인 전까지 `ai-agent/claude/`에 머문다.
