# 웹 버전 설계서 (Web Architecture Design)

**파일 위치**: `ai-agent/claude/261118_웹버전/설계_261118_웹 버전 설계서 v1.0.md` (승인 후 `docs/` 승격 예정)
**작성일**: 2026-11-18
**버전**: v1.0
**설명**: 명세서 FR-13(웹 브라우저 실행)을 구현한 구조, API, 화면 흐름, 보안 조치를 정리한 설계서. 방법론 §2.3 설계 산출물.

---

## 1. 설계 원칙

1. **업무 로직 재사용**: `src/`의 `session`, `quiz`, `daily`, `report`, `vocab`, `user_store`, `settings`, `online_dict`를 그대로 쓴다. 웹 쪽에 규칙을 다시 쓰지 않는다.
2. **화면만 새로 만든다**: PyQt 화면(`src/ui/`)과 `main.py`는 웹에서 쓰지 않는다.
3. **이 PC 안에서만 동작**: 서버는 `127.0.0.1`에만 연다. 외부 전송은 온라인 한영 검색(FR-12)에만 있다.
4. **정답은 서버에만**: 시험 정답은 응답에 넣지 않고, 채점은 서버에서 한다.

## 2. 구성

```
브라우저 (web/static)
  index.html ─ common.js ─ study.js ─ manage.js ─ app.js  (HTML/CSS/JS, 프레임워크 없음)
        │  fetch (JSON, 같은 PC)
        ▼
FastAPI 서버 (web/app.py)  ── TrustedHost 검사 ── 라우트 ~30개
        │
        ├─ web/quiz_registry.py   진행 중 시험 문항 (메모리, 최대 50회분)
        │
        ▼
업무 로직 (src/: session, quiz, daily, report, vocab, user_store, settings, online_dict)
        │
        ▼
data/ 폴더 (voca.csv, users/, settings.json)   ← SMARTVOCA_DATA_DIR로 변경 가능
```

| 파일 | 역할 | 대략 크기 |
|------|------|-----------|
| `web/run.py` | 서버 시작, 기본 브라우저 열기 | 34줄 |
| `web/app.py` | API 라우트, 요청 검사, 응답 모양 | 523줄 (500줄 초과, 분리 대상) |
| `web/quiz_registry.py` | 진행 중 시험 보관 | 49줄 |
| `web/static/common.js` | API 호출, 안전한 요소 생성, 알림, 테마 | 127줄 |
| `web/static/study.js` | 암기, 시험 풀이·결과, 과제 | 475줄 (500줄 미만, 근접) |
| `web/static/manage.js` | 단어 추가, 검색, 보고서, 계정, 옵션 | 417줄 |
| `web/static/app.js` | 메뉴, 해시 이동, 계정 확인 | 100줄 |
| `web/static/style.css` | 테마 변수, 카드, 좁은 화면 | 205줄 |

> `web/app.py`는 CLAUDE.md 원칙 5(500줄 넘으면 분리 제안)에 따라 라우트 묶음별로 나누는 방안을 작업 계획서 W-6에 올렸다.

## 3. 데이터 경로와 공유

| 항목 | 값 |
|------|----|
| 웹 데이터 | `data/` (프로젝트 폴더, 개발 실행과 같음) |
| exe 데이터 | exe 옆 폴더 (`dist/`) |
| 변경 방법 | 환경 변수 `SMARTVOCA_DATA_DIR`에 폴더 경로 지정 |

- 웹과 exe는 데이터를 공유하지 않는다 (명세서 3.20).
- 환경 변수 처리: `config.resolve_base_dir()`에서 가장 먼저 확인한다. 공백만 있으면 무시한다.

## 4. API

모든 계정 요청은 `username`(GET은 쿼리, POST·PUT은 본문)을 받는다. 계정이 없으면 404, 형식이 틀리면 400이다. 계정은 `POST /api/users`로만 만든다.

### 4.1 기본

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/` | 화면 파일 |
| GET | `/api/meta` | 앱 정보 (단어 수, 품사, 유형, 방향, 기간 옵션, 출처 문구, 데이터 폴더) |

### 4.2 계정

| 메서드 | 경로 | 대응 세션 기능 |
|--------|------|----------------|
| GET | `/api/users` | `list_user_keys` |
| POST | `/api/users` | `UserStore.create` (이름 검사 포함) |
| DELETE | `/api/users/{key}` | `delete_account` |
| POST | `/api/users/{key}/reset` | `reset_records` (추가 단어 유지) |

### 4.3 단어

| 메서드 | 경로 | 대응 |
|--------|------|------|
| GET | `/api/words/search?q&mode` | `search_by_english`, `search_by_meaning` (최대 20개) |
| GET | `/api/words/{word}` | 풀에서 찾기 |
| POST | `/api/words` | `add_word` (같은 단어는 뜻 합침, `merged` 응답) |
| PUT | `/api/words/{word}` | `update_custom_word` (추가 단어만) |
| DELETE | `/api/words/{word}` | `delete_custom_word` (추가 단어만) |
| POST | `/api/favorites/{word}` | `toggle_favorite` |
| GET | `/api/online-search?q` | `search_english_translations` (키가 없으면 안내만) |

### 4.4 암기

| 메서드 | 경로 | 대응 |
|--------|------|------|
| GET | `/api/memorize/next?favorites_only` | 후보 선택 (화면과 같은 규칙, 즐겨찾기가 없으면 전체) |
| POST | `/api/memorize/open` | `record_memorize` (같은 날 한 번만 이력) |

### 4.5 시험과 과제

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/test/quiz` | 시험 문항 생성. 문항 수 5~50, 5 단위 검사 |
| POST | `/api/test/wrong` | 최근 시험에서 틀린 단어로 재시험 |
| POST | `/api/quiz/{id}/grade` | 채점과 기록 (과제 시험이면 완수 판정까지) |
| POST | `/api/quiz/{id}/abort` | 중단 (과제 시험이면 미이수 처리) |
| GET | `/api/assignment?username` | 오늘 과제 (없으면 만듦) |
| POST | `/api/assignment/quiz` | 과제 시험 문항 (처리된 과제면 400) |

**문항 응답 형식**: `index, word, direction, kind, prompt, choices`. 정답(`accepted`, `expected_text`)은 채점 응답에서만 나온다.

**채점 응답 형식**: `score, passed, pass_rate, results[]`. `passed`는 과제 시험에서만 값이 있다 (그 외 `null`).

### 4.6 기록, 보고서, 옵션

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/history` | 이력 행 목록 |
| GET | `/api/history/export` | 이력 CSV 내려받기 (이력이 없으면 404) |
| GET | `/api/report?period&start&end` | 완수율, 암기 수, 정답률, 오답 상위 10, 최근 14일 |
| GET | `/api/settings` | 설정 (인증키 값은 제외, `krdict_api_key_set`만 보냄) |
| PUT | `/api/settings` | 설정 갱신 (`krdict_api_key`를 주면 저장, 빈 문자열이면 지움) |

## 5. 주요 흐름

### 5.1 시험

```
1. 화면: 조건 선택 → POST /api/test/quiz
2. 서버: 후보 선택(품사·즐겨찾기) → 정답 단어 무작위 추출 → build_questions
         → 문항을 QuizRegistry에 보관, quiz_id 발급 → 정답 없이 문항만 응답
3. 화면: 문항을 하나씩 풀이, 답은 브라우저에 모아 둠
4. 화면: 제출 → POST /api/quiz/{id}/grade (답 목록)
5. 서버: grade_answers → record_results(시험 구분) → 레지스트리에서 제거 → 결과 응답
```

- 시험 중 브라우저를 닫으면 기록되지 않는다 (데스크톱과 같다).
- 같은 quiz_id로 두 번 채점하면 두 번째는 404다.

### 5.2 과제

```
1. 화면: GET /api/assignment → 오늘 과제 표시 (pending이면 시험 시작 버튼)
2. 화면: POST /api/assignment/quiz → 과제 문항 (단답·4지선다·OX 균등, 방향 복합)
3-a. 제출: grade → record_results(과제시험) + finish_assignment (정답률 80% 이상이면 완수)
3-b. 그만두기: abort → abandon_assignment (미이수, 단어는 다음 날 복습 대기열)
```

### 5.3 계정 선택

- 화면을 열면 계정이 없으므로 계정 화면으로 이동한다.
- 계정을 고르면 메모리(화면 상태)에만 둔다. `localStorage`에 저장하지 않는다 (명세서 3.11).

## 6. 보안

| 위험 | 조치 |
|------|------|
| 외부 기기 접속 | 서버 주소를 `127.0.0.1`로 고정 |
| DNS 재연결로 로컬 서버 호출 | `TrustedHostMiddleware`로 호스트 이름을 `127.0.0.1`, `localhost`, `testserver`로 제한 (testserver는 테스트용) |
| 정답 노출 | 문항 응답에 정답 필드를 넣지 않음. 테스트에서 키 목록을 확인 |
| 인증키 노출 | 설정 응답에서 키 값을 빼고 설정 여부만 보냄. 테스트 `test_settings_update_and_api_key_is_not_returned` |
| HTML 삽입 | 화면은 `textContent`로만 글자를 넣음 (`SV.el`) |
| 잘못된 계정 이름 | 경로 이름 검사 후 400 (`../` 등 차단) |
| 파일 경로 입력 | 이력 CSV는 계정 폴더의 고정 파일만 내려받음 |

**남은 위험**: 같은 PC의 다른 프로그램은 이 서버에 접속할 수 있다. 사용자 계정 인증이 없으므로 공용 PC에서는 주의한다.

## 7. 알려진 제약

- 서버를 끄면 진행 중 시험이 사라진다 (메모리 보관).
- 한 PC에서 한 서버만 실행한다고 가정한다. 여러 탭에서 같은 계정을 동시에 바꾸면 마지막 저장이 이긴다.
- 음성 읽기는 브라우저 음성 기능에 따라 다르다.
- 보고서는 화면에서만 보여 준다. HTML 파일 저장은 하지 않는다.
- 단어 목록 전체를 화면에 보여 주지 않는다 (검색으로 찾음).
