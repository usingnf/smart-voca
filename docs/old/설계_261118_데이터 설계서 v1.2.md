# 데이터 설계서 (Data Design)

**파일 위치**: `docs/설계_261118_데이터 설계서 v1.2.md`
**작성일**: 2026-11-18
**버전**: v1.2
**설명**: 단어 CSV, 사용자 데이터 DB(SQLite), 오류 로그의 스키마와 저장 정책을 정리한 설계서. 방법론 §2.3 데이터 설계 산출물. v1.1에서 사용자 데이터 저장을 파일(JSON·CSV)에서 SQLite(`voca.db`)로 바꾼 내용을 반영했다.

---

## 1. 저장소 개요

| 저장소 | 경로 | 형식 | 쓰기 주체 | 커밋 |
|--------|------|------|-----------|------|
| 단어 원본 | `voca.csv` (`VOCA_PATH`로 지정 가능) | CSV (UTF-8, BOM 있음) | 앱은 읽기만 함. 수집 스크립트가 생성 | 예 (`data/voca.csv`) |
| 사용자 데이터 (계정, 상태, 추가 단어, 이력, 옵션) | `voca.db` (`DB_PATH`로 지정. 기본값 `BASE_DIR/voca.db`) | SQLite 3 | 세션, 옵션 화면 | 아니오 |
| 보고서 | `reports/*.html` (데스크톱 전용) | HTML | 데스크톱 보고서 화면 | 아니오 |
| 오류 기록 | `%LOCALAPPDATA%\SmartVoca\error.log` | 텍스트 | 오류 처리기 | 아니오 |

- `BASE_DIR`은 exe 실행 시 exe 옆 폴더, 개발 실행 시 프로젝트의 `data/` 폴더, 환경 변수 `SMARTVOCA_DATA_DIR`이 있으면 그 폴더다.
- 학교 서버(Docker)에서는 `DB_PATH=/data/voca.db`, `VOCA_PATH=/app/data/voca.csv`로 지정한다 (인터페이스 정의서 3.4).

## 2. 단어 원본 `voca.csv`

### 2.1 열 정의

| 열 이름 | 상수 (`vocab.py`) | 필수 | 설명 | 예 |
|---------|-------------------|------|------|----|
| 단어 | `COLUMN_WORD` | 예 | 영어 표제어 | `abacus` |
| 품사 | `COLUMN_POS` | 예 | `noun`, `verb`, `adj`, `adv`, `other` | `noun` |
| 한글뜻 | `COLUMN_MEANING` | 예 | 쉼표(`, `)로 연결, 최대 3개 | `수판, 산판, 셈판` |
| 영문뜻 | `COLUMN_GLOSS` | 아니오 | 첫 번째 영문 정의 | |
| 출처 | `COLUMN_SOURCE` | 예 | 원천 표시 | `kaikki.org (English Wiktionary 추출, 2026-09-02 덤프)` |
| 라이선스 | `COLUMN_LICENSE` | 예 | 라이선스 표시 | `CC BY-SA 4.0 / GFDL` |
| 유의어 | `COLUMN_SYNONYM` | 아니오 | 쉼표 연결, 최대 10개 | `civet hyena, earthwolf` |
| 예문 | `COLUMN_EXAMPLE` | 아니오 | 영문 예문 한 개 | |

### 2.2 규칙

- 인코딩은 UTF-8이며 BOM을 포함한다 (`utf-8-sig`로 읽는다).
- 한 행이 한 단어다. 같은 단어가 여러 품사로 있으면 행을 나눈다 (품사 필터 테스트에서 확인).
- 셀 안 줄바꿈은 허용한다. 현재 73개 셀에 줄바꿈이 있다 (2026-11-18 확인).
- 열 순서는 `CSV_COLUMNS`를 따른다. 열을 바꾸면 `data/README.md`와 수집 스크립트를 함께 고친다.

### 2.3 현재 값 (2026-11-18 확인)

| 항목 | 값 |
|------|----|
| 데이터 행 수 | 4,000 |
| 유의어 있음 | 2,530 |
| 예문 있음 | 2,940 |

## 3. 사용자 데이터 `voca.db` (SQLite)

### 3.1 테이블 목록

| 테이블 | 한 행의 의미 | 기본 키 | 상위 테이블 |
|--------|--------------|---------|-------------|
| `users` | 계정 한 개 | `user_key` | 없음 |
| `user_state` | 계정 상태 한 개 (JSON) | `user_key` | `users` (삭제 시 함께 삭제) |
| `custom_words` | 계정이 추가한 단어 한 개 | `user_key`, `word` | `users` (삭제 시 함께 삭제) |
| `history` | 이력 한 줄 | `id` (자동 증가) | `users` (삭제 시 함께 삭제) |
| `app_settings` | 앱 전체 옵션 (한 행만 존재, `id = 1`) | `id` | 없음 |

- 외래 키 규칙을 켠 상태로 연결한다. 계정을 지우면 상태, 추가 단어, 이력이 함께 지워진다 (FR-11).
- 테이블은 처음 연결할 때 자동으로 만든다 (`CREATE TABLE IF NOT EXISTS`). 이미 있으면 그대로 둔다.

### 3.2 `users` (계정)

| 열 | 형식 | 설명 |
|----|------|------|
| `user_key` | 문자열 | 소문자로 정규화한 계정 이름 (`normalize_username`) |
| `created_at` | 문자열 | 만든 시각, KST ISO 8601 (초 단위) |

- 계정이 있는지는 이 표로 확인한다 (`user_exists`).

### 3.3 `user_state` (상태)

`state_json` 열에 상태 객체를 JSON 문자열로 저장한다.

| 키 | 형식 | 의미 |
|----|------|------|
| `assignments` | 목록 | 과제 기록. 각 항목은 `date`, `words`, `review`, `new`, `status`, `score` |
| `queue` | 목록 | 미이수 과제 이월 대기열 |
| `stats` | 객체 (단어 → 시도·오답 수·최근 출제일 `last_asked`) | 오답률 계산 근거 (FR-05), 가중 출제 (v1.2) |
| `memorized` | 객체 (날짜 → 단어 목록) | 날짜별 암기 단어. 다음 날 복습 후보 |
| `favorites` | 목록 | 즐겨찾기 단어 (FR-03). v1.0에서는 누락되어 있었다 |

- 생성 기본값은 `user_store.empty_state()`가 정한다.
- 과제 `status`는 `pending`, `completed`, `missed` 중 하나다 (`config.STATUS_*`).

### 3.4 `custom_words` (사용자 추가 단어)

| 열 | 형식 | 설명 |
|----|------|------|
| `user_key` | 문자열 | 계정 |
| `word` | 문자열 | 단어 (기본 키의 일부) |
| `pos` | 문자열 | 품사 |
| `meanings_json` | JSON 배열 문자열 | 한글 뜻 목록 |
| `english_gloss` | 문자열 | 영문뜻 (기본값 빈 값) |
| `synonyms_json` | JSON 배열 문자열 | 유의어 목록 |
| `example` | 문자열 | 예문 |
| `source` | 문자열 | 출처 (추가 단어는 `사용자 입력`) |
| `license` | 문자열 | 라이선스 (추가 단어는 빈 값) |

- 추가 단어 저장은 계정의 기존 목록을 지우고 새로 넣는 방식이다 (한 트랜잭션).
- 초기화(FR-11)는 이 표를 지우지 않는다 (`test_reset_keeps_custom_words`).

### 3.5 `history` (이력)

| 열 (DB) | 화면·CSV 열 이름 | 설명 | 예 |
|---------|------------------|------|----|
| `logged_at` | 일시 | KST 시각, ISO 8601 (초 단위, 시간대 포함) | `2026-11-18T09:12:00+09:00` (예시) |
| `kind` | 구분 | `config.RECORD_*` 중 하나 | `암기`, `시험`, `과제시험` |
| `word` | 단어 | 대상 단어 | `abacus` |
| `direction` | 방향 | `quiz.DIRECTION_*` | `영어→한글` |
| `question_kind` | 유형 | `quiz.KIND_*` (암기는 비움) | `4지선다형` |
| `result` | 결과 | `config.RESULT_*` | `정답`, `오답`, `열람` |
| `user_input` | 입력값 | 사용자가 입력한 답 | |
| `expected` | 정답 | 정답 뜻 | |
| `day` | 일차 | 암기 기록의 학습 일차 (과제 순서, 명세서 3.21). 시험 기록은 비움 (v1.2 추가) | `3` |

- 조회 결과는 화면·CSV와 같은 한글 열 이름(`HISTORY_COLUMNS`)으로 돌려준다.
- 이력 내려받기(웹)와 이력 내보내기(데스크톱)는 같은 열 구성의 CSV를 만든다 (UTF-8 BOM 포함).
- 시험으로 집계하는 구분은 `config.TEST_RECORD_KINDS` (`시험`, `과제시험`)다.
- 암기 이력은 오답률에 넣지 않는다 (명세서 3.18).
- 같은 날 같은 단어 암기는 한 번만 기록한다 (`test_same_word_same_day_adds_history_only_once`).
- v1.2: `day` 열은 암기 기록에만 채운다. `day` 열이 없던 예전 DB는 연결할 때 `ALTER TABLE`로 열을 더한다 (`database._add_missing_columns`).

### 3.6 `app_settings` (옵션)

- 옵션 전체를 JSON 문자열 한 개(`settings_json`)로 저장한다. 행은 `id = 1` 하나뿐이다.
- 키 이름과 기본값은 아래 4장을 따른다.

## 4. 옵션 `app_settings`의 키

| 키 | 타입 | 기본값 | 범위 |
|----|------|--------|------|
| `theme` | 문자열 | `밝게` | `밝게`, `어둡게` |
| `font_size` | 정수 | 10 | 9~16 |
| `exam_count` | 정수 | 20 | 5~50, 5 단위 |
| `exam_direction` | 문자열 | `영어→한글` | 3가지 |
| `memorize_direction` | 문자열 | `영어→한글` | 2가지 |
| `window_width` / `window_height` | 정수 | 900 / 600 | 800~2560 / 540~1600 |
| `krdict_api_key` | 문자열 | 빈 값 | 앞뒤 공백 제거. 서버 응답에는 값을 내보내지 않는다 |
| `online_lookup_enabled` | 불리언 | true | |
| `exam_kinds` | 목록 | 3가지 전부 | 알려진 값만 |
| `exam_pos_keys` | 목록 | 5가지 전부 | 알려진 값만 |
| `exam_favorites_only` | 불리언 | false | |

- 범위를 벗어난 값은 `AppSettings.sanitized()`가 기본값으로 되돌린다. 저장할 때도 같은 검사를 한다.
- 저장된 JSON이 깨졌거나 옵션 행이 없으면 기본값으로 읽는다. 앱은 종료하지 않는다.

## 5. 오류 기록 `error.log`

- 형식: `[YYYY-MM-DD HH:MM:SS]` 시각 줄, 다음 줄부터 트레이스백.
- 파일이 없으면 폴더와 함께 만든다. 쓰기에 실패하면 기록을 건너뛴다.
- 사용자 학습 데이터는 기록하지 않는다.

## 6. 저장 정책

| 항목 | 정책 |
|------|------|
| 쓰기 방식 | 쓰기 한 번이 트랜잭션 한 개다. 블록이 정상 끝나면 저장(commit), 오류가 나면 되돌린다(rollback) |
| 동시 접근 | SQLite 잠금에 맡긴다. 연결 대기 시간은 10초 |
| 손상 데이터 | JSON 형식이 깨진 상태·옵션은 기본값으로 읽는다. 다음 저장 때 덮어쓴다 (v1.0의 파일 격리는 없어짐) |
| 백업 | 자동 백업은 없다. 서버를 멈춘 뒤 `voca.db` 파일을 복사해 보관한다 (운영 정의서 7장) |
| 삭제 | 계정 삭제는 `users` 행을 지우고, 딸린 상태·추가 단어·이력을 함께 지운다 (FR-11). 되돌릴 수 없음 |
| 초기화 | 이력과 상태를 지우고 추가 단어와 즐겨찾기는 남긴다 |
| 용량 | 이력은 행 단위로 쌓이며 자동 정리는 없음 |

## 7. 무결성 규칙

1. 단어 키는 `WordEntry.word`다. 사용자 추가 단어가 공용 단어와 같으면 중복 안내를 띄운다 (`AddWordPage`).
2. 계정 이름은 소문자로 정규화하여 대소문자 차이를 없앤다.
3. 과제는 날짜당 하나다. 같은 날 다시 호출하면 기존 과제를 반환한다 (`test_same_day_returns_same_assignment`).
4. 완수된 과제의 점수는 `complete_assignment`에서만 기록한다.
5. 계정이 없는 곳에는 상태·추가 단어·이력을 쓰지 않는다 (외래 키 규칙이 막는다).

## 8. 기존 파일 데이터의 이관

- v1.0의 `users/<이름>/state.json`, `words.csv`, `history.csv`와 `settings.json`은 `ai-agent/scripts/261125-파일저장소를SQLite로옮기기.py`로 `voca.db`에 옮긴다.
- 이미 DB에 있는 계정과 옵션은 건너뛴다. 원본 파일은 지우지 않는다.
- 이관 절차와 확인 방법은 운영 정의서 9장을 따른다.

## 9. 알려진 한계

- 뜻별 구분이 없는 유의어가 섞여 있을 수 있다 (`data/README.md` 5장).
- `voca.csv`는 열 이름이 바뀌면 읽기가 깨진다. 열 이름은 상수로 관리한다.
- DB 스키마를 바꾸면 기존 `voca.db`를 옮기는 절차가 필요하다. 테이블 버전 관리는 아직 없다.
- 깨진 상태 데이터는 조용히 기본값으로 읽힌다. 원인 파악을 위해 로그를 남기지 않는다.
