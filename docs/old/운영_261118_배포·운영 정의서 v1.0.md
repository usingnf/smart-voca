## 1. 개발 환경

| 항목 | 값 | 확인 방법 |
|------|----|-----------|
| 운영체제 | Windows 11 | |
| Python | 3.11 (기본값, `C:\Users\USER\AppData\Local\Programs\Python\Python311`) | `py -0p` |
| 패키지 설치 | `py -3.11 -m pip install -r requirements.txt` | PyQt6 6.11.0, pyinstaller 6.22.2 |
| 컨테이너 | 사용하지 않음 (호스트에서 직접 빌드) | CLAUDE.md |

> 패키지 설치는 환경 변경이므로 사용자 승인 후 진행한다 (CLAUDE.md 자동 실행 원칙).

## 2. 실행 방법

| 목적 | 명령 | 데이터 위치 |
|------|------|-------------|
| 개발 실행 | `python src/main.py` (프로젝트 루트) | `data/` |
| 테스트 | `python -m unittest discover -s tests -v` | 임시 폴더 |
| 배포본 실행 | `dist/SmartVoca.exe` | exe와 같은 폴더 |

## 3. exe 빌드

### 3.1 명령

CLAUDE.md에 기록된 명령을 그대로 사용한다. 프로젝트 루트에서 실행한다.

```
python -m PyInstaller --noconfirm --clean --onefile --windowed --name SmartVoca --icon ../src/assets/SmartVoca.ico --add-data "../src/assets/SmartVoca.ico;assets" --version-file ../packaging/version_info.txt --paths src --distpath dist --workpath build/pyi --specpath build src/main.py
```

> 명령에 나오는 `../` 경로는 spec 폴더(`build/`) 기준이다. 명령을 다른 폴더에서 실행하면 실패한다.

### 3.2 빌드 전 체크리스트

- [ ] 단위 테스트 전체 통과 (`python -m unittest discover -s tests -v`)
- [ ] `git status`로 의도하지 않은 변경이 없는지 확인
- [ ] `src/assets/SmartVoca.ico` 존재 확인
- [ ] `packaging/version_info.txt`의 제품 이름이 "스마트 보카"인지 확인
- [ ] 이전 `dist/SmartVoca.exe`를 백업하거나 덮어써도 되는지 확인

### 3.3 빌드 후 체크리스트

- [ ] `dist/SmartVoca.exe` 수정 시각이 빌드 시각과 같은지 확인
- [ ] exe를 `voca.csv`가 있는 폴더에서 실행하고 로그인 창이 뜨는지 확인
- [ ] 암기 1회, 시험 1회 진행 후 `users/<이름>/history.csv`에 기록이 생겼는지 확인
- [ ] 강제 오류 확인 (T-2) — 필요할 때만

### 3.4 빌드 결과 기록

| 빌드 날짜 | 파일 크기 | 포함 기능 | 비고 |
|-----------|-----------|-----------|------|
| 2026-11-11 15:11 | 약 37MB (`37,079,879` 바이트) | 아이콘, UI 개선 14건 | 오류 기록 기능 (`874451b`, 15:16 커밋) 이전 |

> 현재 `dist/SmartVoca.exe`는 최신 커밋(`874451b`)보다 먼저 만들어졌다. 오류 기록 기능이 빠져 있다. 재빌드가 필요하다 (작업 계획서 T-1). 빌드는 사용자 승인 후 진행한다.

## 4. 배포 패키지

### 4.1 제출물

| 파일 | 필수 | 설명 |
|------|------|------|
| `SmartVoca.exe` | 예 | 제출물 본체 |
| `voca.csv` | 예 | 단어 데이터. exe와 같은 폴더에 둠 |

### 4.2 실행 시 자동으로 생기는 파일 (exe 옆)

| 파일 | 생성 시점 |
|------|-----------|
| `users/<이름>/state.json`, `words.csv`, `history.csv` | 계정을 만들 때 |
| `reports/*.html` | 보고서를 저장할 때 |
| `settings.json` | 옵션을 저장할 때 |

### 4.3 실행 시 다른 위치에 생기는 파일

| 파일 | 위치 | 생성 시점 |
|------|------|-----------|
| `error.log` | `%LOCALAPPDATA%\SmartVoca\error.log` | 처리되지 않은 오류가 날 때 |

### 4.4 제출 전 확인

- [ ] `dist/`에 `SmartVoca.exe` 하나만 제출 대상으로 준비되어 있는지 확인
- [ ] 제출 폴더에 `users/`, `settings.json`(API 키 포함) 등 개인 데이터가 없는지 확인
- [ ] `data/README.md`의 출처와 라이선스 표시가 최신인지 확인

## 5. 배포 보안

| 항목 | 조치 |
|------|------|
| API 키 | `settings.json`에만 있음. 저장소와 제출 폴더에서 제외 |
| 사용자 데이터 | `.gitignore`의 `users/`, `reports/` 제외 |
| 원본 수집 데이터 | `data/raw/` 제외 (용량) |

## 6. 장애 대응

| 증상 | 원인 후보 | 대응 |
|------|-----------|------|
| 실행 직후 앱이 닫힘 | 처리되지 않은 예외 | `%LOCALAPPDATA%\SmartVoca\error.log` 확인 |
| 한글이 깨짐 | 글꼴 문제 또는 offscreen 실행 | 일반 Windows 실행인지 확인 (CLAUDE.md) |
| 온라인 검색 실패 | 인증키 없음, 인터넷 없음, 시간 초과 | 옵션에서 키 확인, 온라인 검색 끄고 로컬 사용 |
| 계정이 안 보임 | `users/` 폴더 위치가 다름 | exe 옆 폴더인지 확인 |
| 과제가 이상함 | 날짜 기준 (KST) 차이 | 시스템 시간대와 무관하게 KST 기준임을 확인 |
| 이력 파일 깨짐 | 파일 손상 | 손상 파일은 격리 처리됨. 원본 백업 확인 |

## 7. 데이터 복구

| 대상 | 복구 방법 |
|------|-----------|
| 단어 데이터 | `data/voca.csv`를 Git에서 되돌림 (`git checkout -- data/voca.csv`는 변경 확인 후에만) |
| 사용자 이력 | 자동 백업 없음. 사용자가 `export_history`로 내보낸 파일이 있으면 사용 |
| 설정 | `settings.json`을 지우면 기본값으로 시작 |

> 사용자 데이터 삭제는 되돌릴 수 없다. 삭제 전에 해당 폴더를 확인한다 (CLAUDE.md).
