## 1. 개발 환경

| 항목 | 값 | 확인 방법 |
|------|----|-----------|
| 운영체제 | Windows 11 (개발), Linux 컨테이너 (서버 배포) | |
| Python | 3.11 (개발 기본값), 3.13 (서버 이미지) | `py -0p` |
| 패키지 설치 (개발) | `py -3.11 -m pip install -r requirements.txt` | PyQt6 6.11.0, pyinstaller 6.22.2, fastapi, uvicorn, httpx |
| 패키지 설치 (서버) | 이미지 빌드 중 `requirements-server.txt` 설치 | fastapi, uvicorn 등, PyQt6 제외 |
| 컨테이너 (로컬) | 사용하지 않음. exe는 호스트에서 직접 빌드 | CLAUDE.md |
| 컨테이너 (서버) | 학교 서버에서 `Dockerfile`로 이미지를 빌드해 실행 | 5장 |

> 패키지 설치는 환경 변경이므로 사용자 승인 후 진행한다 (CLAUDE.md 자동 실행 원칙).
> 이 PC에는 Docker가 설치되어 있지 않다. 서버 이미지 빌드는 학교 서버에서 확인한다.

## 3. 데스크톱 exe 빌드 (보조 버전)

### 3.1 명령

CLAUDE.md에 기록된 명령을 그대로 사용한다. 프로젝트 루트에서 실행한다.

```
python -m PyInstaller --noconfirm --clean --onefile --windowed --name SmartVoca --icon ../src/assets/SmartVoca.ico --add-data "../src/assets/SmartVoca.ico;assets" --version-file ../packaging/version_info.txt --paths src --distpath dist --workpath build/pyi --specpath build src/main.py
```

> 명령에 나오는 `../` 경로는 spec 폴더(`build/`) 기준이다. 명령을 다른 폴더에서 실행하면 실패한다.

### 3.2 빌드 전 체크리스트

- [ ] 단위 테스트 전체 통과 (`python -m unittest discover -s tests -v`)
- [ ] `git status`로 의도하지 않은 변경이 없는지 확인
- [ ] `src/assets/SmartVoca.ico` 존재 확인
- [ ] `packaging/version_info.txt`의 제품 이름이 "스마트 보카"인지 확인
- [ ] 이전 `dist/SmartVoca.exe`를 백업하거나 덮어써도 되는지 확인

### 3.3 빌드 후 체크리스트

- [ ] `dist/SmartVoca.exe` 수정 시각이 빌드 시각과 같은지 확인
- [ ] exe를 `voca.csv`가 있는 폴더에서 실행하고 로그인 창이 뜨는지 확인
- [ ] 암기 1회, 시험 1회 진행 후 exe 옆 `voca.db`에 기록이 생겼는지 확인 (웹 화면의 이력 내려받기로도 확인 가능)
- [ ] 강제 오류 확인 (T-2) — 필요할 때만

### 3.4 빌드 결과 기록

| 빌드 날짜 | 파일 크기 | 포함 기능 | 비고 |
|-----------|-----------|-----------|------|
| 2026-11-11 15:11 | 약 37MB (`37,079,879` 바이트) | 아이콘, UI 개선 14건 | 오류 기록 기능 (`874451b`, 15:16 커밋) 이전. 파일 저장 방식 |

> 현재 `dist/SmartVoca.exe`는 최신 커밋보다 먼저 만들어졌다. 오류 기록 기능이 빠져 있고, 저장 방식이 파일 기반이다.
> SQLite 전환(2026-11-25) 이후 exe는 재빌드가 필요하다 (작업 계획서 T-1). 빌드는 사용자 승인 후 진행한다.

## 4. 배포 패키지

### 4.1 제출물

> 제출물 형식은 웹 기본 결정(2026-11-25) 후 재확인이 필요하다 (검토 문서 `ai-agent/claude/261125_웹버전기본/` 5항). 아래는 기존 exe 제출 기준이다.

| 파일 | 필수 | 설명 |
|------|------|------|
| `SmartVoca.exe` | 예 (기존 기준) | 제출물 본체 |
| `voca.csv` | 예 (기존 기준) | 단어 데이터. exe와 같은 폴더에 둠 |

### 4.2 실행 시 자동으로 생기는 파일 (exe 옆)

|------|-----------|
| `voca.db` | 처음 실행할 때 (테이블 자동 생성). 계정·이력·옵션이 들어간다 |

### 4.3 실행 시 다른 위치에 생기는 파일

| 파일 | 위치 | 생성 시점 |
|------|------|-----------|
| `error.log` | `%LOCALAPPDATA%\SmartVoca\error.log` | 처리되지 않은 오류가 날 때 |

### 4.4 제출 전 확인

- [ ] `dist/`에 `SmartVoca.exe` 하나만 제출 대상으로 준비되어 있는지 확인
- [ ] 제출 폴더에 `voca.db`(개인 학습 기록과 API 키 포함), `reports/` 등 개인 데이터가 없는지 확인
- [ ] `data/README.md`의 출처와 라이선스 표시가 최신인지 확인

## 5. 학교 서버 배포 (웹, 기본)

### 5.1 이미지 구성

| 항목 | 값 | 근거 |
|------|----|------|
| 기반 이미지 | `python:3.13-slim-bookworm` (버전 태그, latest 아님) | 조건 1 |
| 빌드 | 리포 루트에서 `docker build .` | 조건 1 |
| 의존성 | `requirements-server.txt` (버전 고정, 빌드 중 설치) | 조건 6 |
| 실행 주소 | `0.0.0.0:8080` (uvicorn) | 조건 2 |
| 실행 사용자 | UID 10001, `USER 10001:10001` | 조건 4 |
| 쓰기 가능 위치 | `/data` (DB), `/tmp` | 조건 5 |
| 데이터 파일 | `DB_PATH=/data/voca.db`, `SMARTVOCA_DATA_DIR=/data` | 조건 5 |
| 단어 파일 | `VOCA_PATH=/app/data/voca.csv` (읽기 전용) | 조건 5 |
| 허용 호스트 | `ALLOWED_HOSTS=*` (이미지 기본값) | 점검과 프록시의 Host 이름을 받기 위함 |
| 실행 명령 | `uvicorn --app-dir web app:create_app --factory --host 0.0.0.0 --port 8080 --workers 1 --no-server-header` | 조건 8, ADR-13 |
| 금지 문법 | `# syntax=` 지시어, `RUN --mount=type=ssh|secret`, `RUN --network=`, `RUN --security=` 없음 | 조건 9 |

### 5.2 학교 서버 실행 시 설정할 값

| 항목 | 값 | 비고 |
|------|----|------|
| `ALLOWED_HOSTS` | 이미지 기본값 `*` (모든 호스트 허용). 접근을 좁히려면 학교 접속 호스트 이름 (예: `example.school.ac.kr`) | 앞단 프록시의 Host 이름이 제각각이므로 기본값이 `*`다 |
| `SECRET_KEY` | 사용하지 않음 | 세션 기능이 없다 (조건 7은 "해당 없음") |
| `/data` 볼륨 | 학교 저장 공간을 `/data`에 연결 | 소유자는 UID 10001이어야 한다 |

- 실행 예 (학교 서버 명령으로 바꿔 쓴다): `docker run -p 8080:8080 -v voca-data:/data -e ALLOWED_HOSTS=<접속 호스트> <이미지 이름>`
- 워커는 1개만 쓴다. 늘리면 진행 중 시험이 실패한다 (ADR-13).

### 5.3 서버 배포 전 확인

- [ ] 학교 서버에서 `docker build .`가 성공하는지 확인 (로컬 Docker 미설치)
- [ ] `python:3.13-slim-bookworm` 태그를 학교 레지스트리에서 쓸 수 있는지 확인. 필요하면 패치 버전까지 고정
- [ ] `/data`가 UID 10001이 쓸 수 있는 볼륨인지 확인
- [ ] `ALLOWED_HOSTS`가 기본값 `*`인지, 좁혔다면 학교 접속 호스트 이름인지 확인
- [ ] 인터넷 차단 상태에서도 기본 기능(암기, 시험, 과제, 보고서)이 동작하는지 확인. 온라인 한영 검색만 실패해야 한다

### 5.4 서버 배포 보안 (미결 항목 포함)

| 항목 | 조치 | 상태 |
|------|------|------|
| **계정 인증** | 웹에는 로그인이 없다. 서버 주소에 접근하는 누구나 모든 계정의 데이터를 보고 바꾸고 지울 수 있다 | **미결.** 학교 서버 쪽 접근 제한 또는 로그인 도입이 필요하다 (웹 설계서 6.1) |
| API 키 | `voca.db`의 옵션 행에 저장된다. 이미지와 저장소에는 들어가지 않는다 | 조치 완료 |
| 이미지 내용 | `.dockerignore`로 `.git`, `*.db`, `.env`, `settings.json`, `users/`, `tests/`, `docs/` 제외 | 조치 완료 |
| 실행 권한 | UID 10001, 비루트. 실행 중 `chown`, 패키지 설치, 1024 미만 포트 사용 없음 | 조치 완료 |
| 인터넷 | 실행 중 인터넷이 필요 없다. 온라인 한영 검색은 실패 시 로컬 결과만 보인다 | 조치 완료 |

## 6. 장애 대응

| 증상 | 원인 후보 | 대응 |
|------|-----------|------|
| 데스크톱 실행 직후 앱이 닫힘 | 처리되지 않은 예외 | `%LOCALAPPDATA%\SmartVoca\error.log` 확인 |
| 한글이 깨짐 | 글꼴 문제 또는 offscreen 실행 | 일반 Windows 실행인지 확인 (CLAUDE.md) |
| 온라인 검색 실패 | 인증키 없음, 인터넷 없음, 시간 초과 | 옵션에서 키 확인, 온라인 검색 끄고 로컬 사용 |
| 계정이 안 보임 | `voca.db` 위치가 다름, 또는 기존 파일 데이터를 아직 옮기지 않음 | 데이터 폴더와 `DB_PATH` 확인. 9장 이관 절차 실행 |
| 웹 접속 시 `400 Bad Request` | 실행 시 `ALLOWED_HOSTS`를 좁게 지정했는데 접속 호스트가 빠짐 | `ALLOWED_HOSTS`를 `*`로 되돌리거나 접속 호스트를 넣은 뒤 컨테이너 재시작 |
| 컨테이너가 바로 종료됨 | `/data` 권한 문제, `voca.csv` 없음 | `docker logs` 확인. `/data` 소유자가 10001인지 확인 |
| `unable to open database file` | DB 경로의 폴더가 없거나 쓸 수 없음 | `DB_PATH` 폴더 생성과 권한 확인 |
| `database is locked` | 여러 프로세스가 같은 DB를 동시에 씀 | 웹 서버는 워커 1개인지, 데스크톱과 웹이 같은 DB를 동시에 여는지 확인 |
| 과제가 이상함 | 날짜 기준 (KST) 차이 | 시스템 시간대와 무관하게 KST 기준임을 확인 |
| 옵션이 기본값으로 돌아감 | 옵션 행이 없거나 JSON이 깨짐 | 옵션을 다시 저장. 깨진 값은 다음 저장 때 덮어써진다 |

## 7. 데이터 백업과 복구

| 대상 | 방법 | 주의 |
|------|------|------|
| 사용자 데이터 (`voca.db`) | 서버 또는 앱을 멈춘 뒤 `voca.db` 파일을 다른 곳에 복사 | 실행 중 복사하면 일부만 담길 수 있다. 가능하면 멈춘 뒤 복사한다 |
| 이력 (사용자별) | 웹 화면의 이력 내려받기(CSV) | 사용자 한 명씩 받아야 한다. 자동 백업은 없다 |
| 단어 데이터 | `data/voca.csv`를 Git에서 되돌림 (`git checkout -- data/voca.csv`는 변경 확인 후에만) | |
| 옵션 | `app_settings` 행을 지우면 기본값으로 시작 | API 키도 함께 지워진다 |

- 복구: 백업한 `voca.db`를 `DB_PATH` 위치에 덮어쓴 뒤 앱을 시작한다. 덮어쓰기 전에 현재 파일을 따로 복사해 둔다.
- 사용자 데이터 삭제는 되돌릴 수 없다. 계정 삭제는 계정과 그 기록을 모두 지운다. 삭제 전에 계정 이름을 확인한다 (CLAUDE.md).

## 9. 기존 파일 데이터를 `voca.db`로 옮기기

SQLite 전환 전에 쓰던 `users/` 폴더와 `settings.json`을 옮기는 절차다.

1. 옮길 데이터 폴더(예: `data/`)를 확인한다. 폴더 안에 `users/`와 `settings.json`이 있어야 한다.
2. 프로젝트 루트에서 실행한다.
   ```
   py -3.11 "ai-agent/scripts/261125-파일저장소를SQLite로옮기기.py" --data-dir data --db data/voca.db
   ```
3. 출력에서 계정별 추가 단어 수와 이력 행 수를 확인한다.
4. 같은 명령을 한 번 더 실행하면 모두 "건너뜀"으로 나와야 한다 (중복 이관 방지).
5. 원본 `users/`와 `settings.json`은 지우지 않는다. 확인이 끝나도 한동안 그대로 둔다.

- exe 데이터도 같은 방법으로 옮긴다. `--data-dir`에 exe 옆 폴더를, `--db`에 exe 옆 `voca.db`를 준다.
- 이관 후 계정 수와 이력 수가 맞는지 웹 화면에서 확인한다.
