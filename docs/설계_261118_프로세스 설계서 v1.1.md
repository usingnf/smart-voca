# 프로세스 설계서 (Process Logic)

**파일 위치**: `docs/설계_261118_프로세스 설계서 v1.1.md`
**작성일**: 2026-11-18
**버전**: v1.1
**설명**: 과제 구성, 시험 문항 생성, 채점, 보고서 집계의 단위 기능별 알고리즘과 규칙을 정리한 설계서. 방법론 §2.3 프로세스 설계 산출물. 규칙의 원본은 명세서 3장이며 이 문서는 구현 알고리즘을 설명한다.

## 1. 과제 생성 (`daily.create_today_assignment`)

### 1.1 입력과 출력

- 입력: 사용자 상태(`state`), 오늘 날짜(`today`), 단어 풀(`pool`), 난수 생성기(`rng`)
- 출력: 오늘 과제 한 건 (`date`, `words`, `review`, `new`, `status`, `score`)
- 같은 날 이미 있으면 기존 과제를 반환하고 종료한다.

### 1.2 절차

```
1. 같은 날 과제가 있으면 반환
2. 기한이 지난 pending 과제를 missed로 바꾸고 이월 대기열에 넣음 (close_overdue)
3. 복습 비율을 10%~50% 사이에서 무작위로 정함 (choose_review_count)
4. 복습 단어 수 = round(20 × 비율)
5. 복습 후보 = 이월 단어 + 자주 틀린 단어 + 전날 암기 단어
   - 이월 단어를 먼저 채운다. 상한(복습 단어 최대 10개)을 넘는 이월 단어는 다음 날로 넘긴다
   - 자주 틀린 단어를 복습 수의 최대 50%(반올림)까지 채운다. 오답률이 0보다 큰 단어만, 오답률 높은 순 (v1.1, `REVIEW_ERROR_SHARE`)
   - 부족하면 전날 암기 단어에서 무작위로 채운다 (pick_review_words)
6. 신규 단어 수 = 20 − 복습 단어 수
7. 신규 단어는 풀에서 무작위로 뽑되, 이미 출제된 단어와 복습 단어는 제외 (pick_new_words)
8. 신규 단어가 모자라면 오답률이 높은 단어로 채운다 (pick_high_error_words)
9. 과제를 state.assignments에 추가하고 반환
```

### 1.3 규칙 대응

| 규칙 (명세서) | 구현 |
|---------------|------|
| 과제 20개 (3.2) | `DAILY_ASSIGNMENT_SIZE = 20` |
| 복습 비율 10~50% (3.2) | `REVIEW_RATIO_MIN`, `REVIEW_RATIO_MAX`, `choose_review_count` |
| 복습은 전날 암기 단어 (3.2) | `yesterday_words` |
| 자주 틀린 단어 섞기, 최대 50% (3.2, v1.3 명세서) | `pick_review_words`의 `error_quota`, `REVIEW_ERROR_SHARE` |
| 미이수 편입 상한 (3.4) | `close_overdue`, 상한 10개 |
| 복습 부족 시 신규로 채움 (3.5) | `new_count = 20 − len(review_words)` |

> 명세서 3.2는 "오답률 높은 단어부터 복습으로 다시 출제"라고 정한다. 구현은 신규 단어가 모자랄 때만 이 규칙을 쓴다.

### 1.4 일차 (`daily.day_number`, v1.1 추가)

- 입력: 과제 목록, 날짜. 출력: 과제가 만들어진 순서(1부터). 그 날짜의 과제가 없으면 None.
- 과제 목록의 순서를 그대로 쓴다 (1일차, 2일차). 앱을 열지 않은 날은 과제가 없으므로 세지 않는다.

## 2. 과제 완수 판정 (`daily.complete_assignment`)

- 과제 시험을 끝까지 치르면 정답 수를 세고, 정답률 = 정답 ÷ 문항 수다.
- 정답률이 `PASS_RATE` (0.80) 이상이면 `completed`, 미만이면 `missed`로 바꾼다.
- 시험을 끝까지 치르지 않고 나가면 `abandon_assignment`가 `missed`로 기록한다.

## 3. 시험 문항 생성 (`quiz.build_questions`)

### 3.1 유형 배분 (`build_kind_sequence`, `distribute_counts`)

- 선택한 유형(단답형, 4지선다형, OX형)에 문항을 균등하게 나눈다.
- 나머지는 앞 유형부터 1개씩 더한다.
  - 예: 20문항 → 단답 7, 4지선다 7, OX 6 (명세서 3.3)
  - 예: 7문항 → 단답 3, 4지선다 2, OX 2

### 3.2 방향 배분 (`build_direction_sequence`)

- 방향이 "복합"이면 영어→한글과 한글→영어를 섞어 배분한다.
- 단일 방향이면 모든 문항이 같은 방향이다.

### 3.3 유형별 생성

| 유형 | 함수 | 절차 |
|------|------|------|
| 단답형 | `build_short_question` | 문제 표시 후 직접 입력 |
| 4지선다형 | `build_choice_question` | 정답 1개 + 오답 3개 (`DISTRACTOR_COUNT`). 오답은 `pick_distractors`로 고르며, 정답 뜻과 겹치지 않고 같은 품사를 우선한다 |
| OX형 | `build_ox_question` | 참 또는 거짓 문장을 만들고 O/X로 답함. 참·거짓 개수를 맞춘다 (`is_true`) |

### 3.4 오답 보기 고르기 (`pick_distractors`)

```
1. 후보 풀에서 방향에 맞는 뜻이 있는 단어를 고른다
2. 정답 단어의 뜻 키(meaning_keys)와 겹치는 후보를 뺀다
3. 같은 품사 후보를 먼저 고르고, 부족하면 다른 품사에서 채운다
4. 후보가 DISTRACTOR_CANDIDATE_LIMIT(10)개를 넘으면 그중에서 무작위로 고른다
```

### 3.5 출제 단어 선택 (`sampling.pick_weighted_words`, v1.1 추가)

- 단어마다 가중치(`word_weight`)를 구한다. 기본값 1에 다음을 더한다.
  - 출제 기록이 없으면 +2 (안 본 단어)
  - 오답률 × 2 (`error_rate`)
  - 마지막 출제 날짜(`last_asked`)가 7일 이상 지났거나 날짜가 없으면 +1
- 가중치 비율로 한 개씩 뽑고, 뽑은 단어는 후보에서 뺀다 (중복 없음). 후보가 적으면 후보 수만큼만 뽑는다.
- 웹 시험 시작(`/api/test/quiz`)에만 쓴다. 틀린 단어 재시험과 과제 시험은 기존 방식이다.

## 4. 채점 (`quiz.grade_answers`, `is_correct`)

- 입력은 대소문자와 앞뒤·중간 공백을 무시하고 비교한다 (`normalize_answer`).
- 한 단어에 뜻이 여러 개면 그중 하나만 맞아도 정답이다 (`meaning_keys`).
- OX형은 `O`/`X`만 정답으로 인정한다.
- 결과는 `QuizResult` 목록이며 `score_of`로 정답 수를 센다.

## 5. 오답률 집계 (`daily.error_rate`, `session`)

- 단어별로 `stats[단어]`에 시도 수와 오답 수를 누적한다.
- 오답률 = 오답 수 ÷ 시도 수. 시도가 없으면 0으로 본다.
- 시험(`시험`, `과제시험`)만 집계하고 암기는 넣지 않는다.
- 출제할 때마다 `last_asked`에 날짜(KST)를 기록한다 (v1.1, 3.5 가중치에 쓴다).

## 6. 보고서 집계 (`report.build_summary`)

| 지표 | 계산 |
|------|------|
| 시험 정답률 | 시험 구분 행 중 정답 수 ÷ 시험 행 수 |
| 과제 완수율 | 완수 과제 수 ÷ 기간 내 과제 수 |
| 암기 수 | 암기 구분 행 중 고유 단어 수 |
| 오답 상위 | 오답 수 내림차순, 상위 `TOP_WRONG_WORDS`(10)개 |
| 날짜별 정답률 | 최근 14일, 날짜마다 시험 정답률 |

- 기간은 `period_range`가 정한다: 전체, 최근 7일, 최근 30일, 직접 지정.
- 날짜 기준은 KST다 (`timeutil.kst_today`).

## 7. 온라인 조회 흐름 (`online_dict.search_english_translations`)

```
1. 인증키가 없으면 MSG_NO_KEY로 종료 (네트워크 호출 없음)
2. 검색 주소 생성 (build_search_url)
3. 5초 시간 초과로 요청
4. HTTP 오류 → 서버 오류 메시지
5. 연결 실패·시간 초과 → 오프라인 메시지
6. 응답 XML에서 영어 번역만 추출, 중복 제거 (parse_search_xml)
7. 성공한 결과만 화면에 캐시 (실패는 캐시하지 않음)
```

## 8. 알려진 제약

- 난수를 쓰므로 같은 조건에서도 결과가 다르다. 테스트는 고정 시드 또는 규칙 검사로 확인한다.
- 신규 단어 풀이 좁아지면 (이미 출제된 단어 제외) 과제 구성이 어려워질 수 있다. 4000개 기준에서는 문제가 없다고 보지만 확인 방법은 없다.
