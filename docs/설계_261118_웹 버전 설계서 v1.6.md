# 웹 버전 설계서 (Web Architecture Design)

**파일 위치**: `docs/설계_261118_웹 버전 설계서 v1.6.md`
**작성일**: 2026-11-18
**버전**: v1.6
**설명**: 명세서 FR-13(웹 브라우저 실행)을 구현한 구조, API, 화면 흐름, 보안 조치를 정리한 설계서. 방법론 §2.3 설계 산출물. v1.1에서 웹 버전을 기본 실행 버전으로 정하고, 저장소(SQLite), 서버 배포(Docker) 구성을 반영했다.

---

## 1. 설계 원칙

1. **업무 로직 재사용**: `src/`의 `session`, `quiz`, `daily`, `report`, `vocab`, `user_store`, `settings`, `online_dict`를 그대로 쓴다. 웹 쪽에 규칙을 다시 쓰지 않는다.
2. **화면만 새로 만든다**: PyQt 화면(`src/ui/`)과 `main.py`는 웹에서 쓰지 않는다.
3. **기본 실행 버전**: 웹 버전은 이 프로젝트의 기본 실행 버전이다 (ADR-12). 로컬 실행은 `127.0.0.1`에만 열고, 학교 서버 배포는 Docker 이미지로 한다 (ADR-13).
4. **정답은 서버에만**: 시험 정답은 응답에 넣지 않고, 채점은 서버에서 한다.
5. **저장소는 SQLite 하나**: 사용자 데이터는 `voca.db`에 저장한다 (ADR-11). 단어 원본만 CSV로 읽는다.

## 2. 구성

```
브라우저 (web/static)
  index.html ─ common.js ─ study.js ─ manage.js ─ app.js  (HTML/CSS/JS, 프레임워크 없음)
        │  fetch (JSON)
        ▼
FastAPI 서버 (web/app.py)  ── TrustedHost 검사 ── 라우트 약 30개
        │
        ├─ web/quiz_registry.py   진행 중 시험 문항 (메모리, 최대 50회분)
        │
        ▼
업무 로직 (src/: session, quiz, daily, report, vocab, user_store, settings, online_dict)
        │
        ▼
저장: voca.db (SQLite, DB_PATH)  ·  voca.csv (단어 원본, VOCA_PATH)
```

| 파일 | 역할 | 비고 |
|------|------|------|
| `web/run.py` | 로컬 서버 시작 (`127.0.0.1:8765`), 기본 브라우저 열기 | 기본 실행 진입점 |
| `web/app.py` | API 라우트, 요청 검사, 응답 모양 | 500줄 초과, 분리 대상 (작업 계획서 W-6) |
| `web/quiz_registry.py` | 진행 중 시험 보관 | 메모리 보관 |
| `web/static/common.js` | API 호출, 안전한 요소 생성, 알림, 테마 | |
| `web/static/study.js` | 암기, 시험 풀이·결과, 과제 | 500줄 미만, 근접 |
| `web/static/manage.js` | 단어 추가, 검색, 보고서, 계정, 옵션 | |
| `web/static/app.js` | 메뉴, 해시 이동, 계정 확인 | |
| `web/static/style.css` | 테마 변수, 카드, 반응형 (960·720·480px 단계) | |
| `Dockerfile`, `.dockerignore` | 서버 배포 이미지 정의 | 서버 배포 전용 (ADR-13) |
| `requirements-server.txt` | 서버 실행 패키지 (fastapi, uvicorn 등, 버전 고정) | PyQt6·PyInstaller 제외 |

## 3. 데이터 경로와 공유

| 항목 | 로컬 웹 실행 | 서버 배포 (컨테이너) | 데스크톱 exe |
|------|--------------|----------------------|--------------|
| 사용자 DB | `데이터 폴더/voca.db` | `/data/voca.db` (`DB_PATH`) | exe 옆 `voca.db` |
| 단어 원본 | `데이터 폴더/voca.csv` | `/app/data/voca.csv` (`VOCA_PATH`, 읽기 전용) | exe 옆 `voca.csv` |
| 데이터 폴더 지정 | 환경 변수 `SMARTVOCA_DATA_DIR` | `SMARTVOCA_DATA_DIR=/data` | exe 위치 |

- 데이터 폴더(기본)는 개발 실행이면 프로젝트의 `data/`, exe 실행이면 exe 옆 폴더다.
- DB 파일 경로는 `DB_PATH`가 있으면 그 경로를 쓰고, 없으면 데이터 폴더의 `voca.db`를 쓴다.
- 웹과 exe는 DB 파일이 다르면 데이터를 공유하지 않는다. 같은 파일을 가리키면 같은 데이터를 본다.
- 환경 변수 처리: 공백만 있는 값은 무시한다 (`config.py`).

## 4. API

모든 계정 요청은 `username`(GET은 쿼리, POST·PUT은 본문)을 받는다. 계정이 없으면 404, 형식이 틀리면 400이다. 계정은 `POST /api/users`로만 만든다. 계정 존재 여부는 `voca.db`의 `users` 표로 확인한다.

### 4.1 기본

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/` | 화면 파일 |
| GET | `/api/meta` | 앱 정보 (단어 수, 품사, 유형, 방향, 기간 옵션, 출처 문구, 데이터 폴더) |

### 4.2 계정

| 메서드 | 경로 | 대응 세션 기능 |
|--------|------|----------------|
| POST | `/api/auth/register` | 가입 (사용자명, 8자 이상 비밀번호). 비밀번호 없는 기존 계정이면 비밀번호 설정. 로그인 쿠키 발급 |
| POST | `/api/auth/login` | 로그인. 틀리면 401 (사용자명과 비밀번호를 구분하지 않음). 비밀번호 없는 기존 계정은 409 |
| POST | `/api/auth/logout` | 로그인 쿠키 삭제 |
| POST | `/api/auth/guest` | 게스트 계정을 새로 만들고 로그인 쿠키 발급 (v1.4 추가). 이름은 `guest` + 무작위 8자, 공개 불가 |
| GET | `/api/auth/me` | 로그인 상태 확인. 로그인하지 않았으면 401 |
| PUT | `/api/auth/visibility` | 본인 계정의 공개 여부 설정 (`is_public`) |
| GET | `/api/community/users` | 공개 계정 목록과 진척 통계 (읽기 전용, `community_summary`) |
| GET | `/api/community/users/{key}` | 공개 계정 한 명의 진척 통계. 비공개이면 404 |
| DELETE | `/api/users/{key}` | 본인 계정만 삭제 (다른 계정이면 403). 계정과 딸린 기록 모두 삭제 |
| POST | `/api/users/{key}/reset` | 본인 계정만 초기화 (다른 계정이면 403). 추가 단어와 즐겨찾기 유지 |

v1.3에서 `GET /api/users`와 `POST /api/users`는 없앴다. 계정 목록을 전부 보여 주면 비공개 계정까지 드러나기 때문이다.
로그인하지 않은 `/api/` 요청은 모두 401이다. 예외는 `/api/meta`, `GET /api/settings`, `/api/auth/*`다.
게스트 계정은 `PUT /api/auth/visibility`에서 403을 받는다. 게스트 이름으로 `/api/auth/login`을 하면 401이고, 같은 이름으로 `/api/auth/register`를 하면 409다 (v1.4).

### 4.3 단어

| 메서드 | 경로 | 대응 |
|--------|------|------|
| GET | `/api/words/search?q&mode` | `search_by_english`, `search_by_meaning` (최대 20개) |
| GET | `/api/words/{word}` | 풀에서 찾기 |

| POST | `/api/words/import` | CSV 가져오기 (`parse_word_csv`, `add_words_bulk`). `영단어,뜻`, 기존 단어 건너뜀, 최대 5,000줄. v1.2 추가 |
| PUT | `/api/words/{word}` | `update_custom_word` (추가 단어만) |
| DELETE | `/api/words/{word}` | `delete_custom_word` (추가 단어만) |
| POST | `/api/favorites/{word}` | `toggle_favorite` |
| GET | `/api/online-search?q` | `search_english_translations` (환경 변수 `KRDICT_API_KEY`가 없으면 안내만, v1.6) |

### 4.4 암기

| 메서드 | 경로 | 대응 |
|--------|------|------|
| GET | `/api/memorize/next?favorites_only&today_only` | 후보 선택 (화면과 같은 규칙, 즐겨찾기가 없으면 전체). `today_only` 기본값은 `true`로 오늘 과제 단어만 (v1.6). `false`면 전체 단어 (v1.2) |
| POST | `/api/memorize/open` | `record_memorize` (같은 날 한 번만 이력) |

### 4.5 시험과 과제

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/test/quiz` | 시험 문항 생성. 문항 수 5~50, 5 단위 검사. 단어는 `pick_weighted_words`로 가중 선택 (v1.2) |
| POST | `/api/test/wrong` | 최근 시험에서 틀린 단어로 재시험 |
| POST | `/api/quiz/{id}/grade` | 채점과 기록 (과제 시험이면 완수 판정까지) |
| POST | `/api/quiz/{id}/abort` | 중단 (과제 시험이면 미이수 처리) |
| GET | `/api/assignment?username` | 오늘 과제 (없으면 만듦). 응답에 `day_number`, `memorized_count`, `total_count` 추가 (v1.2) |
| POST | `/api/assignment/quiz` | 과제 시험 문항 (처리된 과제면 400) |

**문항 응답 형식**: `index, word, direction, kind, prompt, choices`. 정답(`accepted`, `expected_text`)은 채점 응답에서만 나온다.

**채점 응답 형식**: `score, passed, pass_rate, results[]`. `passed`는 과제 시험에서만 값이 있다 (그 외 `null`).

### 4.6 기록, 보고서, 옵션

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/history` | 이력 행 목록 (`voca.db`의 `history` 표) |
| GET | `/api/history/export` | 이력 CSV 내려받기. 응답 본문을 서버가 만들며 파일 이름은 `Content-Disposition`으로 준다. 이력이 없으면 404 |
| GET | `/api/report?period&start&end` | 완수율, 암기 수, 정답률, 오답 상위 10, 최근 14일 |
| GET | `/api/settings` | 설정. 인증키 값은 빼고 환경 변수 설정 여부(`krdict_api_key_set`)만 보냄 (v1.6) |
| PUT | `/api/settings` | 설정 갱신. `krdict_api_key`는 받지 않고 무시한다 (v1.6). 인증키는 환경 변수로만 받는다 |

### 4.7 학습 설정과 회차 (v1.5)

| 메서드 | 경로 | 대응 |
|--------|------|------|
| GET | `/api/me/prefs?username` | 학습 설정 (`prefs`)과 고를 수 있는 값 목록 |
| PUT | `/api/me/prefs` | 하루 학습량(5~30, 5 단위)과 복습 비율 상한(10~50%, 10 단위) 저장 (`set_prefs`). 정해진 값이 아니면 400 |

- 보고서 응답의 `runs`는 최근 20회 회차다. 각 항목은 `label`(회차 번호), `at`(날짜), `kind`(시험 구분), `rate`(정답률)다 (`recent_runs`). 회차는 시험 한 번이며 계정 상태에 최대 500회까지 남긴다.


## 5. 주요 흐름

### 5.1 시험

```
1. 화면: 조건 선택 → POST /api/test/quiz
2. 서버: 후보 선택(품사·즐겨찾기) → 정답 단어 무작위 추출 → build_questions
         → 문항을 QuizRegistry에 보관, quiz_id 발급 → 정답 없이 문항만 응답
3. 화면: 문항을 하나씩 풀이, 답은 브라우저에 모아 둠
4. 화면: 제출 → POST /api/quiz/{id}/grade (답 목록)
5. 서버: grade_answers → record_results(시험 구분) → 레지스트리에서 제거 → 결과 응답
```

- 시험 중 브라우저를 닫으면 기록되지 않는다 (데스크톱과 같다).
- 같은 quiz_id로 두 번 채점하면 두 번째는 404다.

### 5.2 과제

```
1. 화면: GET /api/assignment → 오늘 과제 표시 (pending이면 시험 시작 버튼)
2. 화면: POST /api/assignment/quiz → 과제 문항 (단답·4지선다·OX 균등, 방향 복합)
3-a. 제출: grade → record_results(과제시험) + finish_assignment (정답률 80% 이상이면 완수)
3-b. 그만두기: abort → abandon_assignment (미이수, 단어는 다음 날 복습 대기열)
```

### 5.3 계정 선택

- 화면을 열면 `/api/auth/me`로 로그인 상태를 확인한다. 로그인하지 않았으면 로그인 화면만 보이고 메뉴는 숨긴다 (v1.3).
- 로그인한 계정 이름은 메모리(화면 상태)에만 둔다. 로그인 쿠키는 서버가 준 `HttpOnly` 쿠키이며 `localStorage`에 저장하지 않는다 (명세서 3.11, 3.22).

## 6. 보안

| 위험 | 조치 |
|------|------|
| 외부 기기 접속 (로컬 실행) | 로컬 실행은 주소를 `127.0.0.1`로 고정 |
| 외부 기기 접속 (서버 배포) | 서버는 `0.0.0.0:8080`에서 듣는다. 접근 제한은 학교 서버 쪽에서 한다 (미결, 6.1) |
| DNS 재연결로 로컬 서버 호출 | `TrustedHostMiddleware`로 호스트 이름을 제한. 기본 허용 목록은 `127.0.0.1`, `localhost`, `testserver`(테스트용)이고, 환경 변수 `ALLOWED_HOSTS`(쉼표 구분)로 호스트를 더하거나 `*`로 모두 허용한다. 서버 배포 이미지는 기본값이 `*`다 (앞단 프록시의 Host 이름을 받기 위함) |
| 정답 노출 | 문항 응답에 정답 필드를 넣지 않음. 테스트에서 키 목록을 확인 |
| 인증키 노출 | 설정 응답에서 키 값을 빼고 환경 변수 설정 여부만 보냄. 테스트 `test_settings_update_and_api_key_comes_from_env_only` |
| HTML 삽입 | 화면은 `textContent`로만 글자를 넣음 (`SV.el`) |
| 잘못된 계정 이름 | 경로 이름 검사 후 400 (`../` 등 차단) |
| 파일 경로 입력 | 이력 내려받기는 파일 경로를 받지 않는다. 서버가 DB에서 만든 본문만 보낸다 |
| 세션 키 | 세션 기능이 없어 `SECRET_KEY`를 쓰지 않는다 |
| 컨테이너 권한 | UID 10001 사용자로 실행, 쓰기는 `/data`와 `/tmp`만 허용 (운영 정의서 5장) |

### 6.1 남은 위험 (서버 배포)

- **웹 로그인 (v1.3)**: 비밀번호는 PBKDF2-SHA256으로 해시해 저장한다. 세션은 서명된 쿠키(12시간, HttpOnly, SameSite=Lax)이며 서버 메모리에 두지 않는다. 키는 `SECRET_KEY`에서 읽는다.
- 로그인 실패 횟수 제한이 없다. 비밀번호 없는 기존 계정은 누구나 설정할 수 있다 (명세서 5-7). 로그아웃은 쿠키만 지운다 (서버에 폐기 목록이 없다).
- 공용 네트워크에 열면 여전히 위험하므로, 접근 제한을 배포 조건으로 계속 둔다 (운영 정의서 점검 항목).

**남은 위험 (로컬 실행)**: 같은 PC의 다른 프로그램은 이 서버에 접속할 수 있다. 사용자 계정 인증이 없으므로 공용 PC에서는 주의한다.

## 7. 알려진 제약

- **워커 1개 전제**: 진행 중 시험(`quiz_registry`)이 프로세스 메모리에 있다. 워커를 늘리면 채점 요청이 다른 프로세스로 가서 실패한다 (ADR-13).
- 서버를 끄거나 재시작하면 진행 중 시험이 사라진다.
- 한 서버에서 한 DB 파일을 쓴다고 가정한다. 여러 탭에서 같은 계정을 동시에 바꾸면 마지막 저장이 이긴다.
- 음성 읽기는 브라우저 음성 기능에 따라 다르다.
- 보고서는 화면에서만 보여 준다. HTML 파일 저장은 하지 않는다.
- 단어 목록 전체를 화면에 보여 주지 않는다 (검색으로 찾음).
- 온라인 한영 검색은 실행 중 인터넷이 없으면 실패하고 로컬 결과만 보인다 (서버 배포 조건 6).
- 로그인 실패 횟수 제한과 CSRF 토큰이 없다. 쿠키의 SameSite=Lax로 교차 사이트 요청을 막는다 (v1.3).
