# 시스템 아키텍처 설계서 (Architecture Design)

**파일 위치**: `docs/설계_261118_아키텍처 설계서 v1.3.md`
**작성일**: 2026-11-18
**버전**: v1.3
**설명**: 스마트 보카의 계층 구조, 실행 형태(웹 기본, 서버 배포, 데스크톱 보조), 저장 구조, 보안·오류 처리 전략을 정리한 설계서. 현재 구현 기준이며 방법론 §2.3 아키텍처 설계 산출물. v1.1에서 웹 버전을 기본 실행 버전으로 정하고 저장소를 SQLite로 바꾼 내용을 반영했다.

---

## 1. 설계 원칙

1. **화면과 업무 로직 분리**: 화면(웹 화면, 데스크톱 화면)은 `UserSession`만 호출한다 (`src/config.py` 주석, `src/session.py`).
2. **순수 함수 우선**: 문항 생성, 과제 구성, 집계는 입력을 받아 결과를 돌려주는 함수로 만들어 테스트가 쉽도록 한다.
3. **로컬 우선**: 모든 학습 기능은 네트워크 없이 동작한다. 외부 호출은 보조 기능으로만 쓴다.
4. **저장소 하나**: 사용자 데이터는 SQLite 파일 `voca.db` 하나에 둔다. 단어 원본은 읽기 전용 CSV로 둔다. 쓰기는 트랜잭션으로 묶는다 (v1.0의 "파일 기반 저장"을 대체).
5. **설정 중앙화**: 날짜 기준, 과제 크기, 통과 기준 등은 `config.py`에 둔다.
6. **웹 기본**: 기능과 배포의 기준은 웹 버전이다. 데스크톱 버전은 보조 실행 수단이다 (ADR-12).

## 2. 실행 형태

| 형태 | 진입점 | 주소·위치 | 용도 | 상태 |
|------|--------|-----------|------|------|
| 웹 로컬 실행 | `web/run.py`, `웹실행.bat` | `http://127.0.0.1:8765/` | 이 PC에서 학습 (기본 실행) | 기본 |
| 학교 서버 배포 | Docker 이미지 (`Dockerfile`), `uvicorn` | `0.0.0.0:8080`, 학교 프록시 뒤 | 서버 배포 대상 | 기본 (배포) |
| 데스크톱 exe | `src/main.py` → `SmartVoca.exe` | exe 창 | 보조 실행 수단 | 보조 |

- 웹 로컬 실행은 주소를 `127.0.0.1`로 고정한다. 서버 배포는 모든 주소에서 듣고, 받을 호스트 이름은 이미지 기본값 `ALLOWED_HOSTS=*`(모두 허용)로 둔다. 필요하면 환경 변수로 좁힌다.
- 서버 배포 조건(비루트 사용자 UID 10001, 권한 제거, 실행 중 인터넷 차단, 쓰기는 `/data`와 `/tmp`만)은 운영 정의서 5장을 따른다.

## 3. 계층 구조

```
┌──────────────────────────────────────────────────────┐
│ 진입점      web/run.py (로컬) · web/app.py (서버, 기본) │
│             src/main.py (데스크톱, 보조)               │
├──────────────────────────────────────────────────────┤
│ 화면        web/static/ (HTML·JS·CSS, 기본)           │
│             src/ui/ (PyQt6 화면, 보조)                │
├──────────────────────────────────────────────────────┤
│ 세션        session.py (UserSession)                 │
├──────────────────────────────────────────────────────┤
│ 업무 로직   quiz.py  daily.py  report.py             │
│             vocab.py  online_dict.py                 │
├──────────────────────────────────────────────────────┤
│ 저장        user_store.py  settings.py               │
│             database.py (SQLite 연결·트랜잭션)         │
│             vocab.py (단어 CSV 읽기)                  │
├──────────────────────────────────────────────────────┤
│ 공통        config.py  timeutil.py                   │
│             crash_log.py  speech.py                  │
└──────────────────────────────────────────────────────┘
        ▲                         ▲
        │ SQLite 파일 · CSV        │ HTTPS (보조 기능)
  voca.db · voca.csv          krdict.korean.go.kr
```

> v1.2 추가 모듈: `sampling.py` (시험 단어 가중 선택, 업무 로직), `word_import.py` (단어 CSV 읽기, 업무 로직).
> `web/app.py`가 `word_import.parse_word_csv`로 줄을 읽고, 저장은 `UserSession.add_words_bulk`가 한다.

**의존 방향**: 위 계층은 아래 계층만 import한다. 예외는 `session.py`가 `quiz`, `daily`, `user_store`, `vocab`을 함께 쓰는 것이다. 웹 진입점 `web/app.py`는 `src/`의 모듈을 그대로 가져다 쓴다.

## 4. 구성 요소 위상 (Topology)

| 구성 요소 | 위치 | 설명 |
|-----------|------|------|
| `voca.csv` | `VOCA_PATH` (기본: 데이터 폴더) | 단어 4000개, 앱이 읽기만 함 |
| `voca.db` | `DB_PATH` (기본: 데이터 폴더) | 계정, 상태, 추가 단어, 이력, 옵션 (SQLite) |
| `reports/` | 데이터 폴더 | 데스크톱 보고서 HTML (웹은 만들지 않음) |
| `error.log` | `%LOCALAPPDATA%\SmartVoca\` | 처리되지 않은 오류 기록 (데스크톱) |
| 학교 서버 저장 공간 | 컨테이너 `/data` | `voca.db`가 들어 있음. 볼륨으로 붙이며 소유자는 UID 10001 |
| 한국어기초사전 API | 외부 | 사용자 검색 시에만 호출 |

### 4.1 경로 규칙

- 데이터 폴더(`BASE_DIR`)는 환경 변수 `SMARTVOCA_DATA_DIR`이 있으면 그 폴더다. 없으면 exe 실행 시 exe 옆 폴더, 개발 실행 시 프로젝트의 `data/` 폴더다 (`config.resolve_base_dir`).
- DB 파일은 `DB_PATH`가 있으면 그 경로, 없으면 `BASE_DIR/voca.db`다 (`config.DB_PATH`).
- 단어 파일은 `VOCA_PATH`가 있으면 그 경로, 없으면 `BASE_DIR/voca.csv`다 (`config.VOCA_PATH`).
- 읽기 전용 자원(아이콘)은 `sys._MEIPASS`에서 읽는다 (`config.resource_path`).

## 5. 주요 흐름

### 5.1 앱 시작 (웹)

1. `web/app.py`의 `create_app()`이 `VOCA_PATH`의 단어 파일을 읽는다. 파일이 없으면 시작하지 않는다.
2. 허용 호스트 목록(`ALLOWED_HOSTS` 포함)을 정하고 `TrustedHostMiddleware`를 붙인다.
3. 첫 DB 연결에서 테이블을 자동으로 만든다.

### 5.2 앱 시작 (데스크톱)

1. `main()`이 `install_crash_handler()`로 오류 처리기를 등록한다.
2. Windows 앱 식별자를 설정하고 `QApplication`을 만든다.
3. 옵션(`voca.db`의 `app_settings`)과 `voca.csv`를 읽는다.
4. 로그인 창에서 계정을 고르면 `UserSession`을 만들고 메인 창을 연다.

### 5.3 학습 기록

- 암기, 시험, 과제 시험의 결과는 `UserSession.record_*`가 `history` 표에 행을 추가한다.
- 시험으로 치는 기록 구분은 `config.TEST_RECORD_KINDS` 하나로 정한다 (보고서와 세션이 같은 값을 씀).
- 암기 기록에는 일차(`day`)를 함께 남긴다 (v1.2). 일차는 `daily.day_number`가 과제 생성 순서로 정한다.

### 5.4 보고서

- `report.build_summary`가 기간별 기록을 집계한다.
- 데스크톱은 `write_report`가 HTML을 `reports/`에 쓴다. 웹은 집계 결과를 화면에 보여 주고 HTML을 만들지 않는다.

### 5.5 단어 가져오기 (웹, v1.2)

- `POST /api/words/import`가 본문 텍스트를 받는다 (최대 약 200만 자, 5,000줄).
- `parse_word_csv`가 BOM과 머리글을 건너뛰고 `(영단어, 뜻 목록)`과 오류 목록을 만든다.
- `UserSession.add_words_bulk`가 기본 단어·기존 추가 단어·파일 안 중복을 건너뛰고, 나머지를 한 번에 저장한다 (`save_custom_words`는 한 트랜잭션).

### 5.6 시험 출제 (웹, v1.2)

- `POST /api/test/quiz`는 품사·즐겨찾기 조건으로 후보를 좁힌 뒤 `pick_weighted_words`로 단어를 고른다.
- 가중치는 `sampling.word_weight`가 출력 통계(`stats`)와 오늘 날짜로 계산한다. 데스크톱 시험은 바뀌지 않았다.

### 5.7 과제 복습 구성 (v1.2)

- `daily.pick_review_words`는 이월 단어 → 자주 틀린 단어(복습의 최대 50%) → 전날 암기 단어 순서로 채운다.
- 과제 응답에는 `day_number`(일차), `memorized_count`(암기 수), `total_count`(전체 수)가 붙는다.

## 6. 보안·개인정보 전략
## 6. 보안·개인정보 전략

| 항목 | 설계 |
|------|------|
| API 키 | `voca.db`의 `app_settings`에 저장. 저장소와 이미지에서 제외. 코드에 하드코딩하지 않음. 서버 응답에는 값을 내보내지 않음 |
| 세션 키 | 현재 세션 기능이 없어 `SECRET_KEY`를 쓰지 않는다 |
| 계정 | 이름으로 구분, 이름은 소문자로 정규화 (`normalize_username`). 로그인 인증은 없다 |
| 입력 검사 | 계정 이름은 한글·영문·숫자 1~20자 (`USERNAME_PATTERN`) |
| 호스트 검사 | 로컬 실행은 `127.0.0.1`, `localhost`만 허용. 서버 배포 이미지는 프록시의 Host 이름을 받도록 `*`(모두 허용)를 기본으로 두고, 접근 제한은 학교 서버에서 한다 |
| 외부 전송 | 검색어만 전송. 사용자 학습 기록은 전송하지 않음 |
| 로그 | 오류 로그에는 예외 내용만 기록. 사용자 학습 기록은 기록하지 않음 |

**웹 로그인 (v1.3)**: 웹 API는 `/api/` 경로마다 세션 쿠키를 확인한다 (`require_login`). 로그인하지 않으면 401, 다른 계정 이름이면 403이다. 비밀번호는 PBKDF2-SHA256으로 해시해 저장하고, 세션은 서명된 쿠키(12시간, HttpOnly, SameSite=Lax)로 서버 메모리에 두지 않는다. 키는 `SECRET_KEY`에서 읽는다. **남은 위험**: 로그인 실패 횟수 제한이 없다. 비밀번호 없는 기존 계정은 누구나 설정할 수 있다 (명세서 5-7). 접근 제한은 학교 서버 쪽에서도 둔다.

## 7. 오류 처리 전략

| 상황 | 처리 |
|------|------|
| 저장 중 오류 | 트랜잭션을 되돌려 이전 상태를 유지 |
| 상태·옵션 JSON 깨짐 | 기본값으로 읽고 앱은 계속 실행. 다음 저장 때 덮어씀 |
| DB 파일을 열 수 없음 | 연결 오류를 그대로 올린다. 웹은 요청이 실패하고, 데스크톱은 오류 기록 창을 띄운다 |
| 온라인 조회 실패 | `OnlineDictError`로 받아 메시지 표시, 로컬 결과 유지 |
| 처리되지 않은 예외 (데스크톱) | `error.log`에 기록 후 안내 창 (Ctrl+C는 기본 처리) |
| 로그 쓰기 실패 | `False` 반환, 프로그램은 계속 실행 |

| 속성 | 목표 | 확인 방법 |
|------|------|-----------|
| 기능성 | FR-01~FR-13 충족 | 추적 매트릭스 (명세서 4장), 테스트 정의서 |
| 신뢰성 | 기록 손실 없음 | 트랜잭션 테스트, 계정 삭제 연쇄 테스트 (`test_deleting_account_removes_its_data`) |

| 이식성 | Windows 11 단일 exe (데스크톱), Linux 컨테이너 (서버) | 빌드 명령과 실행 확인 (운영 정의서) |
| 유지보수성 | 파일 500줄 이하 권장 | `web/app.py` 500줄 초과 (분리 검토 대상) |

## 9. 알려진 제약

- 단일 PC 기준이며 여러 기기 동기화는 없다. 서버 배포본은 한 대의 서버에서만 실행한다.
- 웹 서버는 **워커 1개**로 실행한다. 진행 중 시험이 프로세스 메모리에 있어서 워커를 나누면 채점 요청이 실패한다.
- 서버를 끄거나 재시작하면 진행 중 시험이 사라진다 (기록되지 않음).
- SQLite는 파일 하나를 여러 프로세스가 동시에 쓰는 구조에 맞지 않다. 현재는 워커 1개 전제로 쓴다.
- 음성 기능은 Windows 명령(데스크톱) 또는 브라우저 기능(웹)에 의존한다.
- 로그인 실패 횟수 제한과 CSRF 토큰이 없다. 쿠키의 SameSite=Lax로 교차 사이트 요청을 막는다 (v1.3).
- 데스크톱과 웹이 같은 `voca.db`를 쓰면 한쪽 변경이 다른 쪽에 바로 보인다. 데이터 경로를 혼동하지 않도록 주의한다.
- 가중 출제, 자주 틀린 단어 섞기, CSV 가져오기는 웹에만 있다. 데스크톱은 기존 방식이며 적용 여부는 명세서 5-5에서 정한다.
- CSV 가져오기의 줄 번호는 CSV 레코드 번호다. 따옴표 안에 줄바꿈이 있으면 편집기의 줄 번호와 다를 수 있다.
