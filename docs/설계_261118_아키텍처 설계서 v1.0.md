**작성일**: 2026-11-18
**버전**: v1.0
**설명**: 스마트 보카의 계층 구조, 구성 요소 위상, 실행 위치, 보안·오류 처리 전략을 정리한 설계서. 현재 구현 기준이며 방법론 §2.3 아키텍처 설계 산출물. (2026-10-21 `설계_261021_구현 설계 v1.0.md`의 내용을 갱신)

## 1. 설계 원칙

1. **화면과 업무 로직 분리**: 화면은 `UserSession`만 호출한다 (`src/config.py` 주석, `src/session.py`).
2. **순수 함수 우선**: 문항 생성, 과제 구성, 집계는 입력을 받아 결과를 돌려주는 함수로 만들어 테스트가 쉽도록 한다.
3. **로컬 우선**: 모든 학습 기능은 네트워크 없이 동작한다. 외부 호출은 보조 기능으로만 쓴다.
4. **파일 기반 저장**: DB 없이 CSV·JSON 파일을 쓴다. 쓰기는 임시 파일 후 교체한다.
5. **설정 중앙화**: 날짜 기준, 과제 크기, 통과 기준 등은 `config.py`에 둔다.

## 2. 계층 구조

```
┌──────────────────────────────────────────────┐
│ 진입점      main.py (AppController)          │
├──────────────────────────────────────────────┤
│ 화면        ui/ (login, main_window, study,  │
│             test, report, options, theme,    │
│             quiz_dialog, chart)              │
├──────────────────────────────────────────────┤
│ 세션        session.py (UserSession)         │
├──────────────────────────────────────────────┤
│ 업무 로직   quiz.py  daily.py  report.py     │
│             vocab.py  online_dict.py         │
├──────────────────────────────────────────────┤
│ 저장        user_store.py  settings.py       │
│             vocab.py (CSV I/O)               │
├──────────────────────────────────────────────┤
│ 공통        config.py  timeutil.py           │
│             crash_log.py  speech.py          │
└──────────────────────────────────────────────┘
        ▲                         ▲
        │ 파일                    │ HTTPS (보조 기능)
  exe 옆 폴더 (data/)         krdict.korean.go.kr
```

**의존 방향**: 위 계층은 아래 계층만 import한다. 예외는 `session.py`가 `quiz`, `daily`, `user_store`, `vocab`을 함께 쓰는 것이다.

## 3. 구성 요소 위상 (Topology)

| 구성 요소 | 위치 | 설명 |
|-----------|------|------|
| `SmartVoca.exe` | 사용자 PC, 실행 파일 | PyInstaller 단일 파일, 읽기 전용 자원(아이콘) 포함 |
| `voca.csv` | exe 옆 폴더 | 단어 4000개, 앱이 읽기만 함 |
| `users/<이름>/` | exe 옆 폴더 | `state.json`, `words.csv`, `history.csv` |
| `reports/` | exe 옆 폴더 | 보고서 HTML |
| `settings.json` | exe 옆 폴더 | 앱 전체 설정, API 키 포함 |
| `error.log` | `%LOCALAPPDATA%\SmartVoca\` | 처리되지 않은 오류 기록 (exe 옆에 파일을 늘리지 않으려고 분리) |
| 한국어기초사전 API | 외부 | 사용자 검색 시에만 호출 |

### 3.1 실행 위치 규칙

- exe로 실행하면 데이터 경로는 `sys.executable`의 폴더다 (`config.resolve_base_dir`).
- 개발 실행(`python src/main.py`)이면 프로젝트의 `data/` 폴더를 쓴다.
- 읽기 전용 자원(아이콘)은 `sys._MEIPASS`에서 읽는다 (`config.resource_path`).

## 4. 주요 흐름

### 4.1 앱 시작

1. `main()`이 `install_crash_handler()`로 오류 처리기를 등록한다.
2. Windows 앱 식별자를 설정하고 `QApplication`을 만든다.
3. `settings.json`과 `voca.csv`를 읽는다.
4. 로그인 창에서 계정을 고르면 `UserSession`을 만들고 메인 창을 연다.

### 4.2 학습 기록

- 암기, 시험, 과제 시험의 결과는 `UserSession.record_*`가 `history.csv`에 한 행씩 추가한다.
- 시험으로 치는 기록 구분은 `config.TEST_RECORD_KINDS` 하나로 정한다 (보고서와 세션이 같은 값을 씀).

### 4.3 보고서

- `report.build_summary`가 기간별 기록을 집계하고, `write_report`가 HTML을 `reports/`에 쓴다.

## 5. 보안·개인정보 전략

| 항목 | 설계 |
|------|------|
| API 키 | `settings.json`에 저장, 저장소 제외. 코드에 하드코딩하지 않음 |
| 계정 | 이름으로 구분, 폴더 이름은 소문자로 정규화 (`normalize_username`) |
| 입력 검사 | 계정 이름은 한글·영문·숫자 1~20자 (`USERNAME_PATTERN`) |
| 외부 전송 | 검색어만 전송. 사용자 학습 기록은 전송하지 않음 |
| 로그 | 오류 로그에는 예외 내용만 기록. 사용자 학습 기록은 기록하지 않음 |

## 6. 오류 처리 전략

| 상황 | 처리 |
|------|------|
| 파일 손상 (JSON 형식 오류) | 파일을 격리하고(`quarantine_file`) 새 상태로 시작 |
| 파일 쓰기 중 실패 | 임시 파일 방식으로 기존 파일 보존 |
| 온라인 조회 실패 | `OnlineDictError`로 받아 메시지 표시, 로컬 결과 유지 |
| 처리되지 않은 예외 | `error.log`에 기록 후 안내 창 (Ctrl+C는 기본 처리) |
| 로그 쓰기 실패 | `False` 반환, 프로그램은 계속 실행 |

## 7. 품질 속성

| 속성 | 목표 | 확인 방법 |
|------|------|-----------|
| 기능성 | FR-01~FR-12 충족 | 추적 매트릭스 (명세서 4장), 테스트 정의서 |
| 신뢰성 | 기록 손실 없음 | 원자적 쓰기 테스트 |
| 응답성 | 온라인 조회가 화면을 멈추지 않음 | 백그라운드 스레드 (`OnlineLookupWorker`) |
| 이식성 | Windows 11 단일 exe | 빌드 명령과 실행 확인 (운영 정의서) |
| 유지보수성 | 파일 500줄 이하 권장 | `ui/study_pages.py` 547줄 (분리 검토 대상) |

## 8. 알려진 제약

- 단일 PC 기준이며 여러 기기 동기화는 없다.
- 음성 기능은 Windows 명령에 의존한다.
- 개발 실행과 exe 실행의 데이터 경로가 다르다. 두 곳의 데이터를 혼동하지 않도록 주의한다.
