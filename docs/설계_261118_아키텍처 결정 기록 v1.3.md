## ADR-01 저장 방식: DB 없이 CSV·JSON 파일 사용 (대체됨)

- **상태**: 대체됨 — ADR-11 (2026-11-25)에서 사용자 데이터를 SQLite로 옮겼다. 단어 원본 CSV는 그대로 유지한다.
- **배경**: 단어 4000개, 사용자 몇 명 규모. 설치 없이 단일 exe로 배포해야 함.
- **대안**
  1. SQLite 같은 내장 DB (재구성된 대안)
  2. CSV·JSON 파일 (채택 당시)
- **결정 근거 (당시)**
  - 제출물이 exe 하나이므로 DB 설치나 서버가 필요 없어야 한다.
  - 데이터가 CSV로 바로 열려 학생이 내용을 확인하고 수정하기 쉽다.
  - 쓰기 실패에 대비한 임시 파일 교체로 손상 위험을 줄였다.
- **결과·제약 (당시)**: 대량 데이터나 동시 접속에는 맞지 않는다. 열 이름 변경 시 호환성 문제가 생긴다.
- **대체 이유**: 학교 서버 배포 조건이 SQLite와 `DB_PATH`를 요구했다. 웹과 데스크톱이 같은 저장 코드를 쓰면서 파일 방식의 손상·동시성 관리가 늘었다.
- **관련**: `데이터 설계서 v1.1`, ADR-11

## ADR-02 GUI 프레임워크: PyQt6

- **상태**: 유효 (데스크톱 보조 버전)
- **배경**: Windows 데스크톱 앱, 한글 표시, 표·탭·대화상자 필요. 단일 exe 배포 가능해야 함.
- **대안**
  1. PyQt6 (채택)
  2. Tkinter (재구성된 대안)
  3. 웹 기반 UI (재구성된 대안. 현재는 웹 버전이 이 역할을 한다, ADR-12)
- **결정 근거**
  - 표, 대화상자, 테마, 스레드를 한 라이브러리에서 제공한다 (`QThread`로 온라인 조회 처리).
  - 설계 시안(`설계_261021_UI 시안`)의 창 구성을 그대로 구현하기 편하다.
- **결과·제약**: PyInstaller로 exe를 만들면 크기가 약 37MB다 (`dist/SmartVoca.exe`, 2026-11-11 기준). 버전은 `requirements.txt`에서 고정한다.

## ADR-03 배포: PyInstaller 단일 파일 + 콘솔 없는 실행

- **상태**: 유효 (데스크톱)
- **배경**: 제출물이 `SmartVoca.exe` 하나여야 함 (CLAUDE.md).
- **대안**
  1. `--onefile --windowed` (채택)
  2. `--onedir` 폴더 배포 (재구성된 대안)
- **결정 근거**
  - 제출 형식이 단일 파일이다.
  - 콘솔 창이 없으면 오류가 사용자에게 보이지 않는다. 이 문제를 ADR-06으로 해결했다.
- **결과·제약**
  - 아이콘 같은 읽기 전용 자원은 임시 폴더(`_MEIPASS`)에서 읽는다 (`config.resource_path`).
  - 사용자 데이터는 exe 옆 폴더의 `voca.db`를 쓴다. 두 경로를 혼동하지 않는다.

## ADR-04 사용자 데이터 위치: exe 옆 폴더

- **상태**: 부분 변경 (ADR-11). 단어 원본과 보고서는 exe 옆 폴더를 유지한다. 사용자 데이터는 exe 옆 `voca.db`다.
- **배경**: 단일 exe 배포에서 데이터를 어디에 둘지 정해야 함.
- **대안**
  1. exe 옆 폴더 (채택)
  2. 사용자 AppData 폴더 (재구성된 대안)
- **결정 근거**
  - `voca.csv`가 exe 옆에 있어야 학생이 직접 확인하고 교체할 수 있다 (CLAUDE.md 배포 방식).
  - 데이터를 찾기 쉽고 이동이 간단하다.
- **예외**: 오류 로그만 `%LOCALAPPDATA%\SmartVoca\error.log`에 둔다 (ADR-06). exe 옆 파일을 늘리지 않으려는 목적이다.
- **결과·제약**: exe를 다른 폴더로 옮기면 데이터 경로도 바뀐다. 서버 배포에서는 `DB_PATH`로 따로 지정한다 (ADR-13).

## ADR-05 단어 데이터 출처: Kaikki (Wiktionary) + 행별 출처 기록

- **상태**: 유효
- **배경**: 영단어 4000개와 한국어 뜻·유의어·예문이 필요함. 직접 입력은 비현실적.
- **대안**
  1. Kaikki(Wiktextract) 원시 데이터 추출 (채택)
  2. 직접 작성 (재구성된 대안)
  3. 상용 사전 API (재구성된 대안)
- **결정 근거**
  - 무료이고 로컬에서 처리할 수 있다. 원시 데이터(약 24GB)는 스트리밍으로 읽었다.
  - 라이선스가 CC BY-SA 4.0 / GFDL이라 출처 표시가 가능하다.
  - 행마다 `출처`, `라이선스` 열을 두어 재배포 조건을 데이터와 함께 보존한다.
- **결과·제약**: 유의어 63%, 예문 74%만 채워짐. 뜻별 구분 없음 (`data/README.md`).
- **관련**: `data/README.md`, 커밋 `46389d9`, `9a7d8b5`

## ADR-06 처리되지 않은 오류: 로그 파일 + 안내 창

- **상태**: 유효 (데스크톱)
- **배경**: exe는 콘솔이 없어서 예외가 나면 앱이 조용히 닫혀 원인을 알 수 없었다 (커밋 `874451b` 메시지).
- **대안**
  1. `sys.excepthook`으로 로그 파일 기록과 안내 창 표시 (채택)
  2. 콘솔 창을 보이게 빌드 (재구성된 대안)
  3. 각 화면에서 try/except로 개별 처리 (재구성된 대안)
- **결정 근거**
  - 한 곳에서 모든 미처리 예외를 잡는다.
  - 콘솔을 보이게 하면 배포 형태가 바뀌고 제출 조건에 맞지 않는다.
  - Ctrl+C는 기본 처리를 유지하여 중단 동작을 바꾸지 않는다.
- **결과·제약**: PyQt 슬롯에서 발생한 예외는 Qt가 추가로 종료시킬 수 있다. **확인 필요**: 실제 exe에서 안내 창 뒤에 앱이 닫히는지 실행으로 확인해야 한다 (`일지_261118_처리되지않은오류기록.md`).
- **관련**: `src/crash_log.py`, `tests/test_crash_log.py`

## ADR-07 온라인 검색: 보조 기능, 실패 시 로컬 유지

- **상태**: 유효. 인증키는 `voca.db`의 `app_settings`에 저장한다 (ADR-11).
- **배경**: 한글 검색어에 대한 영어 번역을 더 얻고 싶으나, 학습 기능은 인터넷 없이도 동작해야 함 (FR-12).
- **대안**
  1. 국립국어원 한국어기초사전 API를 보조로 호출 (채택)
  2. 외부 API 없이 로컬 사전만 사용 (재구성된 대안)
- **결정 근거**
  - 무료이며 공식 API다. 출처 표시 조건이 명확하다.
  - 로컬 결과를 먼저 보여 주고 온라인 결과는 별도 영역에 둔다 (명세서 3.14).
  - 시간 초과 5초, 백그라운드 스레드로 화면 멈춤을 막는다.
- **결과·제약**: 인증키를 사용자가 직접 발급받아 입력해야 한다. 서버 응답에는 키 값을 내보내지 않는다.
- **관련**: 일지 `일지_261028_온라인한영검색.md`, 명세서 3.14

## ADR-08 기록 구분 상수 통일 (`TEST_RECORD_KINDS`)

- **상태**: 유효
- **배경**: `session.py`와 `report.py`가 "시험", "과제시험" 문자열을 각각 따로 정의하고 있었음 (커밋 `874451b`).
- **대안**
  1. `config.py`에 한 번만 정의하고 모두 가져다 씀 (채택)
  2. 각 모듈에 중복 정의 유지 (현행 이전 상태)
- **결정 근거**: 한 곳을 고치면 보고서와 세션 집계가 함께 맞춰진다. 문자열 직접 사용을 없애 오타를 막는다.
- **결과·제약**: 기록 구분을 추가할 때 `config.py`와 `TEST_RECORD_KINDS`를 함께 고쳐야 한다.

- **상태**: 유효
- **배경**: AI 작업 산출물과 승인된 산출물을 구분해야 함.
- **대안**
  1. 작업 문서는 `ai-agent/claude/`, 승인 후 `docs/`로 이동 (채택)

## ADR-11 사용자 데이터 저장소: SQLite(`voca.db`)로 전환

- **상태**: 유효 (2026-11-25, 사용자 선택)
- **배경**
  - 학교 서버 배포 조건이 SQLite와 환경 변수 `DB_PATH`(값 `/data/voca.db`)를 요구한다.
  - 파일 방식은 계정마다 폴더와 여러 파일을 두어, 계정 삭제·초기화·손상 처리가 파일마다 따로 필요했다.
  - 웹과 데스크톱이 같은 저장 코드를 쓰므로 저장 방식을 한 가지로 맞출 필요가 있었다.
- **대안**
  1. 전체를 SQLite로 전환 (채택). 계정, 상태, 추가 단어, 이력, 옵션을 `voca.db` 한 파일에 둔다.
  2. 파일 저장을 유지하고 경로만 `/data`로 옮김 (기각). 학교 배포 조건 5를 충족하지 못한다.
  3. 웹 전용 SQLite를 따로 두고 데스크톱은 파일 유지 (기각). 저장 코드가 두 벌이 된다.
- **결정 근거**
  - 조건 5를 충족한다.
  - 외래 키로 계정 삭제 시 딸린 데이터가 함께 지워져 FR-11 구현이 단순해진다.
  - 저장 코드가 한 벌이 된다 (`src/database.py`, `src/user_store.py`, `src/settings.py`).
- **결과·제약**
  - 단어 원본 `voca.csv`는 읽기 전용 기준 데이터이므로 CSV로 유지한다.
  - 데스크톱 exe도 `voca.db`를 쓴다. 기존 exe 데이터는 이관 스크립트로 옮겨야 한다 (`ai-agent/scripts/261125-파일저장소를SQLite로옮기기.py`).
  - 스키마를 바꾸면 기존 DB를 옮기는 절차가 필요하다. 버전 관리 테이블은 아직 없다.
  - 동시 쓰기는 SQLite 잠금에 맡긴다. 웹 서버는 워커 1개로 실행한다 (ADR-13).
- **관련**: `데이터 설계서 v1.1`, `작업계획_261125_SQLite 전환 v1.0.md`, ADR-01, ADR-04

## ADR-12 기본 실행 버전: 웹 버전

## ADR-13 웹 서버 실행 방식: uvicorn 단일 워커, Docker 이미지

- **상태**: 유효 (2026-11-25)
- **배경**

- **대안**
  1. uvicorn 단일 워커 (채택)
  2. uvicorn 여러 워커 (기각). 시험 시작과 채점이 다른 프로세스로 가면 채점이 실패한다.

  - 워커를 늘리려면 진행 중 시험 정보를 DB나 공유 저장소로 옮겨야 한다.
  - 서버 이미지는 `ALLOWED_HOSTS=*`를 기본으로 둔다. 앞단 프록시가 보내는 Host 이름(`front` 등)이 400으로 막히지 않게 하기 위해서다.
  - 계정 인증은 ADR-18에서 추가했다. 그래도 접근 제한은 학교 서버 쪽에서 함께 한다 (명세서 5-7).
  - 온라인 사전 검색은 실행 중 인터넷이 없으면 실패하고, 로컬 결과만 보인다.
- **관련**: `Dockerfile`, `.dockerignore`, `requirements-server.txt`, `운영_261118_배포·운영 정의서 v1.1.md` 5장

## ADR-14 시험 단어 선택: 가중 출제 (웹)

- **상태**: 유효 (2026-11-26)
- **배경**
  - 명세서 FR-03은 "랜덤하게 출제"라고만 정한다. 균등 무작위는 이미 외운 단어와 안 본 단어가 같은 확률로 나온다.
  - 과제 요구사항 VOCA-FR-022는 안 본 단어, 오래된 단어, 자주 틀린 단어를 더 많이 내라고 요구한다.
- **대안**
  1. 균등 무작위 유지 (기각). VOCA-FR-022를 채우지 못한다.
  2. 간격 반복 알고리즘 (기각). 구현과 설명 비용이 크다. 환경 분석서의 "단순 규칙" 방침과도 맞지 않는다.
  3. 가중 무작위 (채택). 기본 가중치 1, 안 본 단어 +2, 오답률 ×2, 7일 이상 지난 단어 +1. 뽑은 단어는 후보에서 빼서 중복을 막는다.
- **결정 근거**
  - 규칙이 단순하고 설명할 수 있다. 가중치 값은 `config.py`의 `TEST_WEIGHT_*` 상수로 둔다.
  - 데스크톱에는 적용하지 않았다 (명세서 5-5 미정).
- **결과·제약**
  - 상수를 바꾸면 출제 분포가 바뀐다. 테스트는 방향(안 본 단어가 더 자주 나옴)만 확인한다.
  - 같은 단어가 반복해서 나오는 것을 막는 장치는 없다. 오답률이 높은 단어가 자주 나올 수 있다.
- **관련**: `src/sampling.py`, `src/config.py`, 명세서 3.19, `tests/test_basic_requirements.py`

## ADR-15 단어 CSV 가져오기: 기존 단어는 건너뜀

- **상태**: 유효 (2026-11-26)
- **배경**
  - VOCA-FR-003은 `영단어,뜻` CSV를 일괄 등록하라고 하고, 중복 처리 정책은 직접 정해 문서에 적으라고 한다.

## ADR-18 웹 로그인: 표준 라이브러리 PBKDF2 해시와 서명된 세션 쿠키

- **상태**: 유효 (2026-11-26)
- **배경**
  - 과제 도전 기능(VOCA-FR-041~043, 051~053)은 로그인, 해시 비밀번호, 계정별 분리, 다른 계정 진척 보기를 요구한다.
  - 기존 계정은 사용자명만 입력했다 (명세서 3.10). 서버 배포본에는 계정 인증이 없었다 (ADR-13).
  - 서버는 인터넷 없이 실행되어야 하고 의존성은 빌드 때 고정된다 (Dockerfile 구성 조건 6, 7).
- **대안**
  1. 사용자명만 유지 (기각). 도전 기능을 채우지 못하고, 누구나 다른 계정을 열 수 있다.
  2. Starlette `SessionMiddleware` (기각). `itsdangerous` 의존성이 추가되어 `requirements-server.txt`를 바꿔야 한다.
  3. 서버 메모리 세션 (기각). 재시작하면 세션이 사라지고, 워커를 늘리기 어렵다.
  4. bcrypt·argon2 (기각). 외부 패키지가 필요하다.
  5. 표준 라이브러리 PBKDF2 해시와 HMAC 서명 쿠키 (채택).
- **결정 근거**
  - 새 의존성이 없어 `requirements-server.txt`가 바뀌지 않는다.
  - 세션이 서버에 없으므로 재시작과 워커 1개 제약에 영향이 없다.
  - 서명 키는 `SECRET_KEY` 환경 변수에서 읽는다 (R-08). 없으면 시작할 때 무작위로 만든다.
- **결과·제약**
  - `SECRET_KEY`를 주지 않으면 재시작할 때 모든 로그인이 끊긴다.
  - 로그아웃은 쿠키만 지운다. 서버에 폐기 목록이 없으므로 탈취된 쿠키는 만료(12시간)까지 유효하다.
  - 로그인 실패 횟수 제한이 없다. 쿠키의 `Secure` 속성은 로컬 HTTP 실행을 위해 켜지 않았다.
  - 비밀번호 없던 기존 계정은 같은 이름으로 누구나 비밀번호를 정할 수 있다 (명세서 5-7).
- **관련**: `web/auth.py`, `web/app.py`(`require_login`, `/api/auth/*`, `/api/community/*`), 명세서 3.22, `tests/test_auth_unit.py`, `tests/web_api_cases.py`

## ADR-19 과제 제출물을 exe에서 웹 앱으로 변경

- **상태**: 유효 (2026-11-26)
- **배경**
  - `CLAUDE.md`는 제출물을 "최종 `.exe` 파일 1개"로 적었다. ADR-12는 이 부분을 미결로 두었다.
  - 과제 요건(소프트웨어 요건 4.1, 4.4)은 GitHub 리포 URL과 제출 커밋 SHA를 적고, 앱을 학교 서버에 Docker로 올리는 것이다.
- **대안**
  1. exe 제출 유지 (기각). 과제 요건과 맞지 않는다.
  2. exe와 웹을 함께 제출 (기각). 평가 대상이 불분명하고 두 버전을 함께 관리해야 한다.
  3. 웹 앱 제출 (채택).
- **결정 근거**
  - 과제 요건이 웹 앱, 서버 배포, 리포 제출을 요구한다.
  - 데스크톱 exe는 보조 버전으로 리포에 남긴다. 빌드 방법은 `CLAUDE.md`에 보조로 적는다.
- **결과·제약**
  - `CLAUDE.md`의 제출물 줄, 명세서 1 개요, ADR-12 상태를 바꿨다.
  - 학교 제출 폼에는 리포 URL과 웹 앱 SHA를 적는다. exe 파일은 올리지 않는다.
- **관련**: `CLAUDE.md` 프로젝트 정보, 명세서 v1.4 1 개요, 소프트웨어 요건 4.1
